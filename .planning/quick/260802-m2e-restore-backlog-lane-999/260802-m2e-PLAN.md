# Quick Task 260802-m2e: Restore backlog lane 998.x → 999.x

## Problem

`gsd-sdk query phase.add "<description>"` mis-numbers every new phase as **999**. This has
happened five times (phases 52, 54, 56, 57 per STATE.md "Roadmap Evolution", and Phase 69
on 2026-08-02), each time requiring a manual correction of both the number and the entry's
placement in ROADMAP.md.

## Root cause (diagnosed, not assumed)

Not a text-matching bug. `scanSequentialMaxPhaseFromMilestone` requires a literal
`Phase N:` heading, so prose like `999.3-MIGRATION.md` never matches it.

The trigger is on disk. GSD reserves exactly one backlog lane, `999.x`, and both scan
functions in `sdk/dist/query/phase-lifecycle-policy.js` skip it with `if (num >= 999) continue`.
This project has two phase directories numbered **998.x**:

- `.planning/phases/998.2-retrieval-embeddings-reconsolidation-engages-knowledge-updat/`
- `.planning/phases/998.3-scope-aware-provenance-memory-importer/`

998 is not `>= 999`, so `scanSequentialMaxPhaseFromDirs` accepts it:
`maxPhase = 998` → `computeNextSequentialPhaseId` returns **999**.

The directories are mis-named, not mis-placed. Their own content says so:
`998.3-01-PLAN.md` frontmatter reads `phase: 999.3-scope-aware-provenance-memory-importer`,
and ROADMAP.md line 93 refers to `999.3-MIGRATION.md`. Both directories carry the same
mtime (2026-07-29 22:04), consistent with a single bulk rename that shifted 999.x → 998.x
and left every internal reference pointing at 999.x.

## Fix

Rename the directories and their contained files back to the 999.x lane the content already
declares. `git mv` throughout — the six files are tracked and their history should survive.

No file *contents* change: `grep -rn "998"` over both directories returns zero hits inside
files. The string appears only in path names.

## Tasks

1. `git mv` both directories 998.x → 999.x
2. `git mv` the five `998.3-*` files inside the renamed directory to `999.3-*`
3. Verify: `phase.add --dry-run` computes the next sequential phase correctly (70, given
   Phase 69 now exists), and the 999.x lane content is intact

## Success criteria

- [ ] `gsd-sdk query phase.add "<probe>" --dry-run` returns phase_number 70, not 999
- [ ] Both lane directories exist under `999.x` with all six files present
- [ ] `git log --follow` still reaches pre-rename history for a moved file
- [ ] No file contents modified — rename only
- [ ] ROADMAP.md and STATE.md unchanged by this task (the lane is referenced by neither
      except the pre-existing `999.3-MIGRATION.md` prose, which becomes correct again)

## Out of scope

The SDK's silent-failure behavior is an upstream concern, not fixable here: `gsd-sdk`
resolves to an npx-cached package (`~/.npm/_npx/.../get-shit-done-cc/sdk/dist/`), so any
local patch is destroyed on the next update. Worth reporting upstream — a single stray
high-numbered directory silently yields a nonsense phase number with no warning, and the
`>= 999` guard hardcodes the reserved band rather than deriving it.
