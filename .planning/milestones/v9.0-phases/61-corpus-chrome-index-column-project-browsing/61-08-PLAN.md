<objective>
Close GAP-4: schema-anchored docs currently render as free-floating peer nodes (their own "Schemas" section
in the index and an isolated cluster in the graph) because in the live data the promoteScope project-landing
doc_containment edges do not exist yet, so nothing links a schema to its project. Founder direction: nest each
schema under its RELATED project — both in the index tree and in graph grouping/ownership — so schemas only
appear in that project's context.

The relationship IS derivable read-only: a schema belongs to project scope S iff at least one of its
D-37-gated `abstracts` members (type IN ('fact','entity'), tombstoned=0, origin != 'inferred') carries
`node_scope = S` — this is exactly the rule CorpusPromoter.promoteScope uses (corpus-promoter.ts:244-254,
`stmtGetSchemasInScope`). This plan resolves that relationship in the viz server (read-only — no edge writes,
no LLM, per CONTEXT.md's allowance for read-only index payload additions) and nests the schema in both
surfaces. Unresolvable schemas (no gated project member, or no matching project doc) stay in the Schemas
section unchanged.

Purpose: schemas feel "out of place / useless as free-floating peers" (UAT test 4). Nesting gives them a
purposeful home. This plan is server + graph-owner-map only; it deliberately requires NO index.js change
(the server moves resolved schema trees into the `projects` array with a project parentId, and index.js's
existing parentId tree-walk nests them automatically).
Output: resolved schemas nest under their project in /index and group under their project's focus/dim in the graph.

Constraints (hard): viz server stays READ-ONLY — SELECT statements only, no INSERT/UPDATE/edge writes, no LLM.
All new prepared statements compiled once (T-39-07). textContent-only discipline is unaffected (no new rendered
strings). D-37 firewall on the abstracts resolution: tombstoned=0, origin != 'inferred', type IN ('fact','entity').
</objective>

stmtGetSchemasInScope (forward): "schemas where at least one D-37-gated abstracts member has node_scope = ?"
  SELECT DISTINCT e.src AS schemaId FROM edge e
    JOIN node m ON m.id = e.dst
    JOIN node_scope ns ON ns.node_id = m.id
   WHERE e.kind = 'abstracts'
     AND m.type IN ('fact','entity') AND m.tombstoned = 0 AND m.origin != 'inferred'
     AND ns.scope = ?
     AND EXISTS (SELECT 1 FROM node s WHERE s.id = e.src AND s.type='schema' AND s.tombstoned=0)

<!-- viz server /graph doc-node query (server.ts:324-333) — already joins node_scope; a schema doc's slug = schemaId (UUID) -->
