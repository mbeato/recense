# Phase 59 — UI Design Contract

> Visual and interaction contract for the HUD Integration (visible-but-belong overlay) phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Stack: vanilla ES modules + plain CSS over a Three.js/WebGL canvas (`src/viz/`). No React,
> no component library, no Tailwind, no shadcn. This spec formalizes an EXISTING half-built
> glass idiom into named tokens — it does not invent a new design system from zero.

**Visual hierarchy (focal point):** The 3D brain scene is the single primary focal point of
this UI; all HUD chrome (chip, rails, palette, panels) is secondary by design — it recedes
to ghost opacity whenever the user is watching the scene (idle, camera in flight, node
focused) and exists at full presence only while being actively reached for (D-08/D-09/D-10).

### Why this glass language is NOT the slop the old `#tooltip` comment feared (Pitfall 1 resolution)

`styles.css`'s `#tooltip` block carries a dated, deliberate comment rejecting `backdrop-filter`
as "the glassmorphism slop." D-12 now asks the tooltip to join the glass reskin. This is
resolved explicitly, not silently overwritten:

- **The tooltip keeps ZERO `backdrop-filter`.** It receives ONLY the token/hairline/radius
  formalization (moves its literals to the shared token set, adopts the specular-hairline
  border pattern) — it stays a near-opaque contrast-first card exactly as the original
  comment intended. This is the deliberate exception documented in D-12's "restyle only"
  scope, not a regression.
- **The reason the OTHER surfaces' glass is not slop:** every other restyled surface
  (chip/rails/palette/detail/settings/reader) uses a **constructed material** — backdrop
  blur (restrained radius, see Glass Construction table) + a hairline specular edge (inset
  top highlight, not a generic border) + the scene-native aubergine tint (not a foreign
  color) — applied ONLY to genuinely-floating screen-space chrome, never to in-scene
  elements (D-13) and never stacked with glow or drop-shadow (items 3/9 above). The rejected
  "slop" was floating frosted cards on a gradient-blob background with no hairline
  construction and no restraint on which surfaces got it; this is the opposite: one
  disciplined recipe, applied by rule, on a locked dark palette, with the tooltip
  deliberately excluded from the blur portion of it.

## Glass Construction Recipe (named tunables — Claude's Discretion, pinned)

Two elevation tiers, both extending the EXISTING `#panel` idiom (`styles.css:97-108`,
already ~80% of this recipe) — not a new invention:

| Token | Value | Applies to |
|-------|-------|------------|
| `--glass-bg-ambient` | `rgba(26, 18, 32, 0.66)` | Chip, icon rail, topics rail at rest (existing `#panel` value, reused verbatim) |
| `--glass-bg-focused` | `rgba(26, 18, 32, 0.90)` | Palette, detail panel, settings panel, reader takeover (content-bearing surfaces needing stronger contrast — between the existing `#panel` 0.66 and `#detail`'s existing 0.93) |
| `--glass-blur-sm` | `8px` | Chip, rails (thin bars; smaller blur = lower compositing cost per RESEARCH A3 perf caution) |
| `--glass-blur-md` | `14px` | Palette, detail, settings, reader (existing `#detail`/`#panel` already use 12px; small bump formalized as the "larger panel" tier) |
| `--glass-border` | `rgba(170, 150, 180, 0.12)` | Ambient-tier hairline border (existing `#panel` value) |
| `--glass-border-focused` | `rgba(140, 150, 165, 0.16)` | Focused-tier hairline border (existing `#detail` value) |
| `--glass-specular` | `inset 0 1px 0 rgba(255, 255, 255, 0.06)` | Specular hairline highlight — top edge only, additive to the border, on ALL glass surfaces except the tooltip (Pitfall-1 exception above). This is a material-construction detail, NOT the banned elevation drop-shadow (item 9). |
| Tooltip exception | No `backdrop-filter`; `background: rgba(20, 14, 26, 0.93)` (existing, unchanged) | `#tooltip` only — token/radius formalization, no blur, no specular (contrast-first by design) |

**Aubergine tint discipline:** every glass surface stays inside the existing
`rgba(26,18,32,*)` (surface) / `rgba(170,150,180,*)` and `rgba(139,112,144,*)` (hairline)
families already used pervasively in `styles.css`. Do not introduce a new saturated violet
when picking "aubergine tint" values (anti-slop item 2).

## Motion Tokens

| Token | Value | Usage |
|-------|-------|-------|
| `--ease-out-soft` | `cubic-bezier(0.22, 1, 0.36, 1)` | ALL chrome transitions (existing value, `styles.css:44-45`) — soft ease-out only, no bounce (anti-slop item 4, D-11) |
| `--motion-fast` | 120ms | Hover/focus micro-states; focus-deepen recede (D-10 — "drop to ghost immediately") |

| `HUD_IDLE_TIMEOUT_MS` | 4000 (provisional — ratchet at D-15 checkpoint) | Idle timer before ambient chrome recede (D-08); intentionally decoupled from `stats.js`'s existing 1200ms scene-drift threshold per RESEARCH Pitfall 2 |

`height` (D-09, no layout shift; consistent with the `transition.js` opacity-only lesson).

## Compact/Popover Mode Gating (carries the existing lock forward)

The tray's ≤500px compact popover stays glance-only — no new chrome, no palette (hard
out-of-scope, CONTEXT.md). New chip/rails/palette DOM MUST be reachable by the EXISTING
`@media (max-width: 500px), (max-height: 500px)` hide rule (`styles.css:420-435`) — either
nest the new elements as descendants of the existing hidden container, or add explicit new
hide rules for their IDs following the identical pattern. The `⌘K` keydown listener itself
must also be gated behind the existing `.mode-window` check so the shortcut does not even
arm inside the popover (RESEARCH Pitfall 7).

## Typography

| Role | Size | Weight | Family | Line Height |
|------|------|--------|--------|-------------|
| Label (eyebrow/tag — tooltip tip-tag, section-header uppercase micro-labels) | 10px | 400 | system-ui | 1.3 |
| Body (default UI text — palette results, settings/detail/reader labels, tooltip title; existing global value, unchanged) | 13px | 400 | system-ui | 1.5 |
| Heading (palette section headers — "Nodes" / "Topics" / "Commands", chip legend header) | 12px | 600 | system-ui, `letter-spacing: 0.06em`, uppercase | 1.2 |
| Mono/Instrument (chip node-count readout, palette input text, rail state text — NEW consumer of the vendored font this phase) | 13px | 400 | vendored `JetBrainsMono-Regular.ttf` | 1.4 |

Heading-vs-body size note: the 12px heading sits 1px BELOW the 13px body deliberately —
hierarchy is carried by weight 600 + uppercase + 0.06em letter-spacing (the standard
instrument-panel eyebrow-header treatment), not by size; a larger heading would fight the
"chrome recedes, scene dominates" hierarchy this phase is built around.

**Only two weights exist in this contract: 400 (regular) and 600 (semibold).** The vendored
mono file is a **single cut (Regular/400 only)** — do NOT synthetically embolden it (browser
faux-bold) and do NOT fetch a second weight from a CDN (vendor-everything rule). If a mono
context needs emphasis, use color/opacity/letter-spacing, never a fabricated bold weight.

`@font-face` addition (new, this phase — the font asset itself is not new):
```css
@font-face {
  font-family: 'JetBrains Mono HUD';
  src: url('../vendor/fonts/JetBrainsMono-Regular.ttf') format('truetype');
  font-weight: 400;
  font-display: swap;
}
```

## Icon System

- Inline hand-authored SVG only (no icon font, no emoji, no vendored icon package).
- Style: outline/stroke, matching `apps/tray/src/popover.ts`'s existing icon exactly —
  `viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
  stroke-linecap="round" stroke-linejoin="round"`, rendered at 14–16px in the rail.
- Rail holds 4–5 core icons max (D-02): reader, settings, corpus, recenter, search magnifier.
- **Every rail icon carries both a tooltip (`title` or CSS tooltip) and an `aria-label`,
  using the labels declared in the Copywriting Contract:** reader → `Open reader`,
  settings → `Open settings`, corpus → `Open corpus view`, recenter → `Recenter view`,
  magnifier → `Search (⌘K)`. No icon ships without an accessible name.
- Icon color: `currentColor` inherits from the surrounding chrome text color (secondary/30%
  tier) at rest; NEVER amber (accent is scene-reserved, see Color section).
