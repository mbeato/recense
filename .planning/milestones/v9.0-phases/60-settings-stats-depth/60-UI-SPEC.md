# Phase 60 — UI Design Contract

> Visual and interaction contract for the Settings Stats Depth (usage + brain-health
> dashboards) phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Stack: vanilla ES modules + plain CSS over the existing `src/viz/` frontend. No React, no
> component library, no Tailwind, no shadcn. This spec extends the Phase-59 Liquid-Glass HUD
> language (D-01, hard dependency) and the Phase-57 activity-palette identity-hue system — it
> does not invent a new visual language. **Auto-chain run: no user available; every open item
> below is a concrete default, not a question, per CONTEXT.md D-01..D-15 + "Claude's
> Discretion."**

**Placement (D-02/D-03):** a full-window route-level takeover — same structural tier as the
existing `#corpus-graph` (replaces the 3D brain while open, not a side panel like `#reader`) —
holding two full-width tabs: **Usage** | **Brain Health**.

## Full-Window Takeover & Navigation Contract

Structural precedent: `#corpus-graph` (`src/viz/css/styles.css:1228-1246`) — `position: fixed;
inset: 0; z-index: 5; display: none` → `.open { display: block }`, opacity-fade companion class,
replaces `#graph` rather than overlaying it.

| Element | Contract |
|---------|----------|
| Host element | New full-window host (e.g. `#stats-view`), `position: fixed; inset: 0`. **z-index: 6** — one tier above `#corpus-graph` (5), still below `#hud-chip`/`#hud-rail` chrome (10) and the palette (49/50). Only one of {brain `#graph`, `#corpus-graph`, `#stats-view`} is visible at a time — opening this view hides the other two, mirroring corpus.js's toggle discipline |
| Background | **Near-opaque flat fill, NOT glass** — `rgba(23, 15, 29, 0.97)` (reuse existing `--surface-index-panel` token verbatim). Rationale below (Glass Discipline) |
| Open transition | `display:none→block` + opacity `0→1` over `var(--motion-slow)` (220ms) `var(--ease-out-soft)` — same tokens Phase 59 locked for panel enter/exit, no bounce (anti-slop item 4 carries forward) |
| Entry points | (1) Settings panel "View usage stats →" link (D-04, replaces the old readout block). (2) New ⌘K palette command, id `open-stats`, label **`Open stats`**, `visibleIn: ['brain','reader','corpus']` (same pattern as the existing `open-settings`/`open-corpus` entries in `palette.js`) — opens directly on the **Usage** tab (matching the settings-link entry point's default) |
| Close | Header `×` button (mirrors `#reader-close`/`#settings-close`) + `Escape` key while open (mirrors the existing per-panel Escape handler pattern in `reader.js`/`settings.js`) |
| Tabs | Two full-width tab buttons, **Usage** / **Brain Health**, Heading typography (below). Active tab: 2px solid `var(--accent-toggle-mauve)` underline + `--text-bright` text. Inactive: `--text-recede`, no underline, hover → `--text-hover-slate` |
| Range switcher (D-12) | 4 pill buttons: `7d` `30d` `90d` `all-time`, Body typography, only visible on charts that support windowing (all Usage-tab time-series + node-growth on Brain Health). Active state reuses the same `--accent-toggle-mauve` fill/border as the tab underline (10% accent — see Color). Selecting `all-time` switches bucket granularity to weekly (D-12) |
| Refresh (D-15) | Icon button (refresh glyph) + adjacent `"as of {HH:MM:SS}"` mono timestamp, top-right of the takeover header, next to the `×`. Fires on open (auto) and on click (manual) — no auto-refresh timer, no SSE |
| Compact/tray gating | `#stats-view` (and its trigger surfaces) MUST be reachable by the existing `@media (max-width: 500px), (max-height: 500px)` hide rule (`styles.css:420-435`), following the exact Phase-59 pattern: either nest as a descendant of the existing hidden container or add an explicit hide rule for its id. Because the palette itself is gated behind `.mode-window` (Phase 59 lock) and the compact tray never shows the settings panel, `#stats-view` is unreachable from compact mode by construction — this is a verification checklist item, not new gating logic to build |

### Glass Discipline (why this surface does NOT get `backdrop-filter`)

The Phase-59 D-14 anti-slop invariant test greps `styles.css` and asserts `backdrop-filter`
appears **only** inside the locked D-12 selector list (chip, rails, palette, `#detail`,
`#settings-panel`, `#reader`, `.toast`). `#stats-view` and its internal chart cards are **new
selectors outside that list** — adding blur to them would either (a) silently fail the machine
check (good — it *should* fail) or (b) require extending the locked allow-list, which this
phase does not have a mandate to do. The simplest, most surgical choice: **this surface never
requests glass.** It follows the `#corpus-graph`/`#index-panel` precedent instead — full-window
content hosts use a **near-opaque flat surface**, not floating glass chrome. Chart cards inside
use flat backgrounds + hairline borders only (see Chart Construction Contract). This keeps the
D-14 invariant untouched and matches the anti-slop item-1 discipline ("glass reserved for
genuinely-floating screen-space chrome... never glass-on-glass").

| Sub-surface | Background | Border | Blur |
|-------------|-----------|--------|------|
| `#stats-view` (full-window host) | `rgba(23, 15, 29, 0.97)` (`--surface-index-panel`) | none (edge-to-edge) | none |
| Chart card | `rgba(26, 18, 32, 0.4)` (new flat token, aubergine family) | `1px solid var(--divider-faint)` | none |
| Stat readout tile (last sleep-pass, headline numbers) | same as chart card | same | none |

## Chart Construction Contract (D-05/D-06/D-07)

Two SVG primitives cover every chart in this phase — **no sparklines** (D-06 explicitly chose
the full-polish tier over big-numbers+sparklines):

| Element | Spec |
|---------|------|
| Line chart | 1.5px stroke, no fill under the line (no area gradient — keeps the flat-surface restraint), rounded line joins |
| Bar chart | Fill at 0.75 alpha of the series color + 1px stroke at full alpha; used for kind-mix (grouped) and per-feature/per-model split (stacked) |
| Axes | Y-axis: value, auto-scaled, minimum always 0, "nice" tick step (~4-5 ticks). X-axis: time, tick label `"MMM D"` (e.g. `Jul 8`) for daily buckets, same format for weekly-bucket tick (labels the bucket start date) — executor picks stride to keep ~5-8 visible ticks regardless of window length |
| Gridlines | Horizontal only, `rgba(140,150,165,0.08)` (existing `--section-divider-faint` token), no vertical gridlines (keeps the chart uncluttered — restraint per the inherited anti-slop discipline) |
| Legend | 8×8px square swatch (2px corner radius) + Body-13px label, placed top-right of the chart card header row |
| Hover / nearest-point (D-07) | Vertical crosshair line (`1px solid var(--glass-border-focused)`) + 4px-radius dot at the nearest data point in the series' full-alpha color, plus a tooltip. **Tooltip reuses the existing `#tooltip` component verbatim** (no blur, `rgba(20,14,26,0.93)` bg, Body-13px — Phase 59's Pitfall-1 exception carries forward unchanged) rendering the format `"{MMM D} — {value}"`, e.g. `Jul 8 — 42.3k tokens` |
| Hover state — NO glow | Per the inherited anti-slop contract (item 3), hover states brighten opacity/stroke-width only — **zero `box-shadow`/`filter: drop-shadow` glow anywhere on chart chrome.** The dot marker and crosshair are flat geometry, not a glow effect |
| Number formatting | Token counts: reuse `fmtTokens()` verbatim (`settings.js:478-482` — `1.2M`/`34.5k`/plain). Retail-$ headline: 4-decimal precision (`toFixed(4)`), matching the existing `settings.js` convention (honest about subscription micro-costs). $ axis ticks: 2-decimal abbreviation (`$0.02`, `$1.45`) — the axis needs to stay compact, the headline keeps full precision |
| Time-range scrubbing (D-06) | Interpreted as the D-12 button-based range switcher (7d/30d/90d/all-time) **plus** the D-07 hover-scrub tooltip above — **not** a separate drag-brush selector. This is a deliberate scope-narrowing default (Claude's Discretion) to avoid inventing an unspecified complex interaction; the two locked mechanisms together satisfy "time-range scrubbing" as read in context |

## Spacing Scale

Declared values for the new full-window surface — multiples of 4. The `xs`/`sm`/`md`/`lg` tier
reuses Phase-59's HUD values verbatim; this larger content surface adds the `xl`/`2xl`/`3xl`
tier the compact HUD chrome never needed:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Legend swatch-to-label gap, badge padding |
| sm | 8px | Compact element spacing (tab-to-underline gap, icon-to-timestamp gap) |
| md | 16px | Chart card internal padding, range-switcher pill gaps |
| lg | 24px | Gap between chart cards within a tab, tab-bar-to-content gap |
| xl | 32px | Takeover header padding (top/sides) |
| 2xl | 48px | Gap between major chart groups (e.g. burn chart vs. per-feature/per-model row) |
| 3xl | 64px | not used this phase (reserved, no element needs page-level spacing at this scale in a single-route takeover) |

Exceptions: none.

## Typography

| Role | Size | Weight | Family | Line Height | Usage |
|------|------|--------|--------|-------------|-------|
| Label | 10px | 400 | system-ui | 1.3 | Axis tick labels, legend labels, event-marker chip text, empty/error captions |
| Body | 13px | 400 | system-ui | 1.5 | Chart card titles, tab-adjacent copy, table/list rows, tooltip text (reuses existing tooltip Body role verbatim) |
| Heading | 12px | 600 | system-ui, uppercase, `letter-spacing: 0.06em` | 1.2 | Tab labels (Usage / Brain Health), chart-group section subheads |
| Display | 28px | 400 | `JetBrains Mono HUD` | 1.2 | Headline numbers only: total tokens, retail-$ equivalent, node count — emphasis carried by size + `--text-bright` color, never a fabricated bold (the vendored file is Regular-only, same constraint Phase 59 locked) |

Heading sits below Body in size (12px vs 13px) deliberately, carrying hierarchy through weight
+ uppercase + letter-spacing rather than size — same discipline Phase 59 established for its
section headers, kept consistent here.

**Only two weights exist in this contract: 400 (regular) and 600 (semibold).** No third weight,
no synthetic bold on the mono family.

pre-existing sites (Pitfall 6), not new Phase-60 chrome.

## Empty / Sparse / Error State Contract

(Claude's Discretion item, CONTEXT.md — "fresh installs must not render broken charts")

| Condition | Behavior |
|-----------|----------|
| Ledger has zero rows (fresh install, Usage tab) | Show the empty-state copy above in place of every chart; do not render an axis/empty-grid shell |
| `consolidation_event` has zero rows (fresh install, Brain Health tab) | Same pattern — empty-state copy, no empty chart shell |
| A single data point exists (sparse, not empty) | Render the chart with one point + a flat/zero baseline rather than failing; no interpolation across a gap the data doesn't support |
| Fetch fails (network/500) | Per-tab error copy above, with the existing refresh button as the retry affordance — no separate "try again" link (avoids a second, redundant CTA) |
| Fewer than 4 models/features present | Render only the series that exist — no zero-padded placeholder series, no invented legend entries |
