<objective>
Close the single BLOCKER from `65-VERIFICATION.md`: the D-11b `event_ts` staleness guard is silently inert for cold-start-minted beliefs, so a stale backfilled contradiction can still silently revert a newer status — the literal DRIFT-04 failure, live at shipped defaults (`statusDriftEnabled: true`, `statusDriftEventTsGuard: true`, `src/lib/config.ts:914,916`).

Purpose: `SUPPORTING_EVENT_TYPES` (`src/consolidation/status-drift.ts:143-150`) excludes `'unrelated'` on the rationale "not evidence about this node's value." That rationale is wrong for the mint case: the consolidator's `'unrelated'` branch (`consolidator.ts:1356-1376`) emits `node_id` = the freshly minted node with `candidate_id: null` — it IS that node's founding evidence, exactly like `'extend'`, which is already included. Every brand-new tracked entity's first status email takes that branch (no existing candidate → auto-unrelated at `consolidator.ts:947-973`, no judge call), so `latestSupportingEventTs` returns `null`, the guard abstains as `'unknown-prior-ts'`, and the stale claim proceeds unguarded into the UNMODIFIED `routeContradiction` — which, at fresh-node resistance, reconciles and tombstones the newer belief. The verifier reproduced this directly (offer at day 30 minted via `'unrelated'`, reverted by a rejection dated day 10 ingested afterwards).

Output: a one-member set change with corrected rationale, the unit assertions that currently lock the buggy exclusion inverted, and an e2e regression case that exercises the genuine cold-start mint path the existing suite's `establishBelief()` helper structurally cannot reach.

**Not in this plan:** no change to `routeContradiction` / `isOscillation` / `countDistinctProvenance` / `src/consolidation/update-decision.ts` (pinned byte-for-byte by `tests/pe-machinery-lock.test.ts`); no schema change; no config change; no `EMISSION_ELIGIBLE_EVENT_TYPES` change; nothing touching the three open `human_verification` items (WR-01 farming bar, WR-03 quote-stripper idempotence, the Plan 65-10 Task 3 ENABLE/HOLD decision) — those are correctly gated on a founder review and are not gaps.
