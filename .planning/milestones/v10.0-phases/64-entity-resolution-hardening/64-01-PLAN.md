<objective>
Close 63-VERIFICATION/63-REVIEW **WR-01** (source-agnostic intent-field threading) BEFORE any resolver consumes those fields, per CONTEXT **D-10**.

Today `src/consolidation/consolidator.ts` copies `claim.intent_status` / `claim.intent_entity` / `claim.intent_confidence` onto `ClaimDecision` for **any** episode source. D-11's "gmail-only isolation" is enforced only in prompt text — so an extraction response from a transcript, `claude-code`, or `granola` episode that smuggles intent fields (prompt injection, model drift, or merged-mode parse) threads them straight through. Phase 64 makes resolution consume those fields, so this must become structural first.

Purpose: make gmail-only isolation a property of the code, not of a prompt.
Output: one hoisted `gmailSourced` predicate + three gated fill sites + a three-route regression test.
</objective>
