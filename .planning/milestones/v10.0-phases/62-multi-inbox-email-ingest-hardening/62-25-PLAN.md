<sequencing_decision>
**The CR-11 hard gate lands in a LATER wave than the leak fixes — option (a).**

Turning `NFDANGER_leak` into a hard gate while CR-05/06/07/09/10 are still open would fail
immediately with ~19 leaks and force either a bound re-tune (a repeat of CR-11 itself) or nineteen
hand-dispositioned `it.fails` rows that the very next plan would flip. Option (a) sequences this plan
into wave 19, after 62-20 (declaration layer), 62-22 (comment/`<style>` layer) and 62-24 (attribute
layer) have landed, so the gate closes over a codebase that already passes it.

The risk option (a) carries is that residual leaks remain when this plan runs. That is handled
explicitly and non-negotiably: any residual leak must be attributed to a NAMED mechanism with its own
structural predicate and its own `it.fails` reproduction — the pattern NF-01/03/04/05/REG-01 already
use. Re-tuning a magnitude bound to absorb a residual is forbidden and is the exact defect this plan
exists to close. If a residual cannot be attributed to a named mechanism, STOP and report it: an
unattributable leak is a new finding, not a tolerance to widen.

Known-open, OUT-OF-SCOPE-to-fix mechanisms expected to still feed the bucket when this runs, each
already locked as an `it.fails`: NF-03 (comma-separated selector list rejected all-or-nothing),
NF-04 (blockless `@media;` at-rule misattributing the next rule's block), NF-05 (CDO/CDC not
ignorable at the stylesheet top level per §5.4.1). NF-01 (CDO truncation) is expected to have CLOSED
in 62-22 — check `62-22-SUMMARY.md` rather than assuming either way.
</sequencing_decision>

<the_two_defects>
1. **The gate is a counter.** `runDifferential` (`tests/css-liveness-differential.test.ts:295-307`)
   pushes to `failures` in exactly ONE place — a lost `VISIBLE_SENTENCE` (`:289-293`). Every genuine
   leak (`classLive && classPresent`) goes unconditionally into `newlyFiled.NFDANGER_leak`, asserted
   only as `toBeLessThan(pairCount * 0.05)` (`:344-346`, `:378-380`, `:471-473`). So the three test
   titles ("both directions, zero unclassified divergences") describe something that cannot happen:
   there is no such thing as an unclassified leak, because the leak bucket needs no predicate to
   enter. The correct shape already exists in this codebase — `tests/strip-hidden.test.ts:1354-1400`'s
   fuzz probe pushes leaks into `leakFailures` and asserts `toEqual([])`.

2. **The judge shares the defect layer with the judged.** `tests/support/css-liveness-oracle.ts:37-70`
   is a line-for-line copy of production's twelve declaration regexes. The file's own residual claim
   (`tests/css-liveness-differential.test.ts:41-53`) says the only shared layer is the tokenizer and
   that the oracle's parse and selector-validity layers are independent. That is materially
   incomplete: the declaration-signature layer is 100% shared, by copy-paste, and it is where CR-05's
   leaks were. Its doc comment also still describes production as a "brace-partition scan" deleted in
   62-17.
</the_two_defects>
