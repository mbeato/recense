<objective>
Migrate the CSS **declaration-signature** layer to the token stream, the way 62-17 migrated the
selector layer — and remove the two remaining structural failure modes on that path (a frame the
walk abandons at EOF, and a harvest bound that fails open).

Purpose: `62-VERIFICATION.md` independently reproduced four live leaks in this layer against the
shipped `dist/` build. All four exist because the selector side reads tokens while the declaration
side still regex-scans `css.slice(frame.contentStart, start)` — raw, untokenized text, comments and
escapes included — and because the walk's two bookkeeping decisions (evaluate only on `}`, abandon
on cap overflow) both discard information rather than fail safe. This is the same argument 62-17
made for selectors, applied to the half that was never migrated.

Output: a declaration signature computed from tokens at both call sites, an EOF-drained frame stack,
no fail-open harvest bound, a CRLF-correct escape decoder, and a locked repro for every payload the
verifier reproduced.
</objective>

<why_a_raw_slice_can_never_agree>
A conformant CSS engine removes comments and decodes `\`-escapes at tokenize time, before any
declaration is ever read. A regex over the raw source is therefore comparing against a string the
engine never sees. Both directions of that disagreement are live today and both were independently
reproduced:

  under-strip  `.legal{display:/*x*/none}`  engine: hidden   recense: not hidden  -> LEAK
  under-strip  `.legal{display:\6eone}`     engine: hidden   recense: not hidden  -> LEAK
  under-strip  `style="display:/*x*/none"`  engine: hidden   recense: not hidden  -> LEAK
  over-strip   `.legal{/*display:none*/color:red}`  engine: shown  recense: deleted

The last row is `WR-12`, which is OUT OF SCOPE for this round as a finding. Do not add tasks or
acceptance criteria chasing it. It is listed here because the correct fix for the first three
closes it as a side effect; if it does, record that as an incidental closure in the SUMMARY's
deviation section rather than claiming credit for scope you were not given.
</why_a_raw_slice_can_never_agree>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| attacker-authored `<style>` content -> `harvestFromStylesheet` | The adversary controls every byte of the stylesheet, including comment placement, escape encoding, brace termination and rule count |
| attacker-authored inline `style` attribute -> `isHiddenStartTag` | Same adversary, a different syntactic path into the same signature decision |
| `stripHiddenContent` output -> `record.content` -> future classifier | The leaked bytes are read by an LLM; this is an indirect prompt-injection sink |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-20-01 | Information disclosure | `hasHidingSignature` over raw declaration text | mitigate | Signature is computed from a token reconstruction (Comment -> one space, ident-bearing tokens escape-decoded) at BOTH call sites; a raw-slice call is banned by a shipped source guard (Task 3) |
| T-62-20-02 | Information disclosure | `harvestFromStylesheet` EOF frame abandonment | mitigate | Frame stack drained after tokenization; the evaluate-and-add path is one shared local function so the `}` branch and the drain cannot diverge |
| T-62-20-03 | Denial of service (of the control) | `MAX_HARVESTED_SELECTORS` fail-open | mitigate | Cap deleted; if the measured fallback fires, overflow fails CLOSED with no sender-controlled bytes surviving — never proceed with a knowingly incomplete hidden-set |
| T-62-20-04 | Spoofing | escape-encoded selector name vs attribute value | mitigate | CRLF consumed as one separator per §3.3, matching css-tree `ident.decode`; CR/CRLF/FF rows locked in the escape-decode test block |
| T-62-20-05 | Denial of service | re-tokenizing declaration slices | mitigate | Only `hasPrelude` frames are evaluated and their slices are pairwise disjoint, so total re-tokenized text <= input length; asserted by the 1 MiB measurement in Task 2 |
| T-62-20-06 | Tampering | over-strip destroying legitimate mail | mitigate | `disp/*x*/lay:none` control asserts a dropped comment does not join adjacent idents; the 1 MiB measurement reports both cost and correctness |
</threat_model>
