<objective>
Close the three Critical findings in `62-REVIEW.md`, all of which falsify roadmap Success Criterion #3
(EMAIL-03: "hidden or invisible content ... is deterministically stripped before any content reaches the
extractor"). All three live in `src/source/strip-hidden.ts`.

**BL-01 is a net regression this phase introduced.** Plan 62-09 narrowed `STYLE_BLOCK_RE`'s unquoted-attribute
class from `[^>]` to `[^'"<>]`, excluding `<`. Per HTML §13.2.5.36 (attribute value, unquoted state) a `<` is a
parse error but is *appended to the attribute value* — the tag continues to the next unquoted `>`. So
`<style x=a<b>` is a valid `<style>` start tag in every conforming parser. Confirmed during planning by running
the real module (`src/source/strip-hidden.ts`, via `tsx`) side by side against a patched copy:

| input | shipped output | required output |
|---|---|---|
| `<style x=a<b>.legal{display:none}</style>ok<span class="legal">PAYLOAD_A</span>` | `.legal{display:none}okPAYLOAD_A` | `ok` |
| `<div x=a<b style="display:none">PAYLOAD</div>Visible.` | `` (empty — visible prose destroyed) | `Visible.` |
| `<style>.legal{display:none}</style foo>ok<span class="legal">PAYLOAD_B</span>` | `okPAYLOAD_B` | `ok` |
| `<style>.legal{display:none}</style/>ok<span class="legal">PAYLOAD_B2</span>` | `okPAYLOAD_B2` | `ok` |

Row 1 fails twice over: the class-hidden `PAYLOAD_A` reaches the classifier's token stream (the EchoLeak-class
defect EMAIL-03 exists to close), and the raw stylesheet leaks in as prose. Row 2 is the same root cause in the
over-removal direction. Rows 3-4 are BL-02: both forms close the element per the RAWTEXT-end-tag-name state and
stage 4's `ANY_TAG_TOKEN_RE` accepts both, so stage 4 deletes the `<style>` block while stage 2 harvested
nothing — the evidence that the span is hidden is destroyed and the span's text survives. That is precisely the
cross-stage boundary bug class (T-62-43) 62-09's doc comment claims to prevent.

**This plan consciously reverses 62-09's stated reasoning.** 62-09 excluded `<` to keep stage 2 in agreement
with stage 4. They do agree — they agree on *failing*, and the shared failure is the leak. Agreement on a wrong
boundary is not the invariant worth preserving. The correct form of that invariant is: all four literals agree
because they are built from ONE fragment, and that fragment matches the HTML tokenizer.

**BL-03** is a coverage gap, not a regression: `INVISIBLE_CODEPOINTS_RE` is a hand-maintained enumeration of 139
codepoints that omits the Variation Selectors Supplement `U+E0100–U+E01EF` (the 2025 arbitrary-byte smuggling
carrier, adjacent to the Tags block that IS covered), `U+FE00–U+FE0F`, the bidi embed/override/isolate controls,
`U+200E`/`U+200F`/`U+061C`, `U+034F`, `U+206A–U+206F`, the Hangul fillers, and `U+2028`/`U+2029` — all verified
