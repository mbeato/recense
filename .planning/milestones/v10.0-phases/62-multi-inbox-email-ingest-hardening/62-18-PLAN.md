## T62-91 is worse than reported, and the fix is not a re-sizing

Measured during planning, in isolation, at exactly the 1,048,576-code-unit cap boundary. Left
column is today's `html.matchAll(STYLE_BLOCK_RE)`; right column is the linear replacement this
plan specifies (a `START_TAG_RE` walk plus a monotone close-tag cursor with break-on-exhaustion),
prototyped and run on the same inputs in the same process:

| shape at exactly 1,048,576 code units | `STYLE_BLOCK_RE` | linear walk |
|---|---|---|
| bare `<style>` repeated (unit 7) — T62-91's own worst case | **23,249 ms** | **0.3 ms** |
| 62-15's Shape T, 4 attribute pairs (unit 56) | 2,887 ms | 0.2 ms |
| single unquoted attribute triple (unit 20) | 8,381 ms | 0.2 ms |
| **`<style ` repeated with NO `>` until the final byte** — never measured by any prior wave | **156,223 ms** | **2.5 ms** |
| well-formed `<style>.g{display:none}</style>` repeated (unit 31) | 2.5 ms, 33,825 matches | 3.6 ms, 33,825 blocks |

Two things follow.

**(a) The verification under-reported the worst case.** The `<style ` -with-no-`>` shape costs
**156 seconds** at exactly the cap boundary — 156x the wave's 1000 ms budget and 7x worse than the
22.7 s the verifier found. It is reachable end-to-end: stage 0 (Bound A) truncates from the first
`<` that follows the LAST `>`, so a body whose only `>` is its final byte is not truncated at all
and reaches `harvestHidingSelectors` in full. Re-sizing the cap to accommodate this shape would
require dropping it to roughly 8 KB, which would break legitimate HTML mail.

**(b) The linear walk removes the mechanism, not just the cost.** `START_TAG_RE`'s attribute region
is built from the shared `ATTRS` fragment, which *permits* an unquoted `<` per HTML §13.2.5.36. So
`<style<style<style…>` is ONE start tag, not thousands of failing scans — this is exactly Bound A's
existing amortization argument (62-14), now applied to stage 2 as well. Close tags are then found
by a cursor that only moves forward, and the first failure to find any further `</style` proves no
later `<style` can find one either, so the walk stops. Total work is O(n).

On the pathological shapes the two columns also disagree on *result*: `matchAll` finds 0 blocks (it
requires a close tag) while the linear walk finds 1 block whose content runs to end of input. That
is a deliberate behavior change, specified and tested below.
</measurements_from_planning>
