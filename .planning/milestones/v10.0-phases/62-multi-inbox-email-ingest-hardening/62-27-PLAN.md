  <behavior>
    Each named predicate becomes a two-part decision: the structural shape is present AND removing
    that shape from the generating CSS makes the leak disappear.

    - NF-05: counterfactual is `css` with every top-level `<!--` / `-->` token removed.
    - NF-04: counterfactual is `css` with the blockless semicolon-terminated at-rule prelude removed.
    - NF-03: counterfactual is `css` with the non-bare sibling of the probe's comma list dropped.

    In each counterfactual the differential re-runs BOTH sides — `liveHidingSelectors(counterfactual)`
    and `stripHiddenContent(wrapper(counterfactual))` — and attribution succeeds only when the probe
    is STILL live in the counterfactual AND the marker is now ABSENT from production's output.

    Three outcomes, all explicit:
      - counterfactual removes the leak and the probe stays live -> attributed, mechanism counter += 1
      - counterfactual leaves the leak -> `failures.push` with a `DIFFERENT MECHANISM` label, the
        generating input, the counterfactual input, both oracle verdicts and both outputs verbatim
      - counterfactual makes the probe non-live (the test is vacuous) -> `failures.push` with a
        `COUNTERFACTUAL VACUOUS` label and the same verbatim payload

    Cost: the counterfactual runs only on the leak branch, never on the (overwhelmingly common)
    no-leak path, so total runtime stays in the same band. Record the before/after wall clock for the
    full file in the SUMMARY.
  </behavior>
