<objective>
Close the three warnings whose failure mode is a leak, and leave the next verification pass an honest
residual register instead of a coverage claim.

Purpose: three of `62-REVIEW.md`'s open warnings are not cosmetic.

- **WR-09** — `applyRemovalRanges` (`:467-477`) assumes its ranges are ascending and non-overlapping;
  the argument lives in `mergeCommentAndElementRanges`' prose and is never checked. If a nested range
  ever reaches it, the cursor moves BACKWARDS and the trailing `html.slice(cursor)` re-emits text an
  earlier range was supposed to delete. The failure mode of a broken containment argument is a
  content leak, in the one function every stage's output flows through.
- **WR-10** — the close-tag end scan (`:679-680`) uses a bare `html.indexOf('>', closeEnd)`, so
  `<div style="display:none">SECRET</div foo="a>b">tail` emits `"b\">tail"`. The hidden payload is
  removed, but sender-controlled in-tag bytes reach `record.content`, which the module's own "every
  remaining tag is removed" contract says cannot happen.
- **WR-05** — ~14 deleted identifiers are still referenced ~60 times in the doc block, two of them as
  live "see X below" navigation. `62-VERIFICATION.md` singles this out as *the direct mechanism of
  CR-01*: the justification comment that shipped the round's first blocker described code 62-24 had
  deleted. Comment drift in this module is a defect class, not a tidiness issue.

Output: a range applier that cannot re-emit, a quote-aware close boundary, a doc block a test keeps
honest, and the phase's residual register.
</objective>
