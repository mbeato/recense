This repo compiles to CommonJS (`tsconfig.json`: `"module": "commonjs"`, `"moduleResolution":
"bundler"`, `outDir: dist`, `rootDir: "."`) and ships `dist/src/**` as the runtime artifact. An
ESM-only package is therefore a real risk, not a formality: `dist/src/source/strip-hidden.js` will
`require()` it. Node >= 22.12 can `require()` a synchronous ESM graph, so ESM-only is not
automatically disqualifying — but it must be PROVEN against the built artifact, not assumed. Note
`moduleResolution: "bundler"` resolves types through the `import` condition while emitting
`require()`, so `tsc --noEmit` passing does NOT prove the runtime path works.

Both candidates ship their own TypeScript types (unlike css-tree), so no ambient `.d.ts` is expected
to be needed. If one IS needed, it belongs under `src/types/` and must declare only the adopted
surface, matching `src/types/css-tree-tokenizer.d.ts`'s pattern.
</candidate_facts>

<what_the_module_actually_needs>
Three uses, all offset-based. The module is a RANGE-DELETING string transformer over the original
source — it deletes `[start, end)` spans and passes everything else through byte-for-byte. It is NOT
a parse-then-serialize pipeline, and it must not become one: its documented contract includes
idempotence and "every entity except `&nbsp;`/`&#160;` is left literal", both of which a tree
serialization would break (`&amp;amp;` -> `&amp;` -> `&` across repeated passes).

  1. HTML comment ranges — `[start, end)` of every comment, including bogus comments and an
     unterminated comment running to EOF (stage 3, and the CR-10 precondition for stage 2).
  2. `<style>` element ranges — content start/end and element end, with RAWTEXT semantics
     (stage 2's harvest).
  3. Start tags — element name, per-attribute DECODED values, and the tag's source range
     (stages 4/5, CR-07).

Criterion (2) of the evaluation is precisely whether the candidate supplies all three as offsets
into the ORIGINAL source string.
</what_the_module_actually_needs>
