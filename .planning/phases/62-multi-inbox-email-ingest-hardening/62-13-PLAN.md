**The closed enumeration `stripCssComments` is built from — state this in the code so a reviewer can check
closure instead of re-deriving it.** CSS Syntax Level 3 §4.3.1 ("consume a token") invokes §4.3.2 ("consume
comments") at EVERY token boundary, so `/*` starts a comment at every token boundary without exception. It
therefore fails to start a comment only when the `/` has already been consumed by an inner loop that has not
returned to a token boundary. Exactly three productions can consume a `/`:

1. **§4.3.5 consume a string token** — consumes any code point until the matching quote, a newline (which makes it
   a bad-string and returns to the token stream), or EOF; a backslash consumes the following code point.
2. **§4.3.6 consume a url token**, unquoted form only — after an ASCII-case-insensitive `url(` and any leading
   whitespace, if the next code point is NOT `"` or `'`, it consumes any code point until `)`, EOF, or a bad-url
   code point; §4.3.14 ("consume the remnants of a bad url") likewise consumes to `)` or EOF. A backslash consumes
   the following code point. A QUOTED `url("…")` is a function token followed by a string token, so it is covered
   by (1) and must NOT be treated as a raw url span — otherwise a `)` inside the quoted URL desynchronises the scan.
3. **§4.3.7 consume an escaped code point**, reached from ident-sequence consumption (§4.3.11/§4.3.12) — a `\`
   followed by any code point that is not a newline consumes that code point, so `\/` eats the `/`. A `\`
   followed by a newline is NOT a valid escape, so a `/*` after it IS a comment.

The list is closed because no other production consumes a `/` away from a token boundary: `/` is not an ident code
point, numeric consumption cannot include it, and every remaining token is single-code-point or delimiter-shaped.
Note the near-miss that is NOT on the list: every other function token (`calc(`, `attr(`, …) tokenises normally
inside, so `/*` IS a comment there — `url(` is the only raw-consuming function.

Per HTML §13.2.5.1-13.2.5.20, inside a raw-text or escapable-raw-text element the ONLY thing that can end the
element is its own end tag: `</` + the element's name, followed by whitespace, `/`, or `>`. Nothing else in the
body is a tag. Nesting is impossible, so the first matching end tag closes the element — this is why
`<script>var s = "</script>";</script>` famously ends at the first `</script>`. The current depth-counting scan
models neither rule.

The RAWTEXT / escapable-RAWTEXT element set to use: `script`, `style`, `title`, `textarea`, `iframe`, `noembed`,
`noframes`, `xmp`. `noscript` is deliberately EXCLUDED and the exclusion must be stated in the code: mail clients
parse with scripting disabled, where `<noscript>` content is ordinary markup, so the existing depth-counting scan
is the faithful one there — and stage 4 deletes the element wholesale either way.
