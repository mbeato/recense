<why_the_token_stream_closes_these>
Each of the three most recent findings is a disagreement between the hand-rolled scanner and one
§4.3 production. The token stream removes the disagreement rather than patching it:

| Finding | Scanner's error | What the token stream gives instead |
|---|---|---|
| VF-01 (§4.3.2) | a comment adjacent to a selector survived into the reconstructed selector text and failed the bare-selector regex | comments are separate tokens and are skipped; a selector's tokens are never text-adjacent to a comment |
| FB-01 (§4.3.5) | raw-text brace counting desynchronized after a malformed string | `{`/`}` are **tokens**; a `BadString` cannot contribute a brace, so depth tracking cannot desynchronize |
| CR-04 (§4.3.6) | the literal substring `url(` opened a raw span anywhere it appeared | `xurl(` is a `Function` token and `url(` is a `Url` token; the tokenizer decides, and there is no substring test to fool |
| escaped selectors (§4.3.7) | `BARE_CLASS_SELECTOR_RE` rejected any name containing a backslash, so a browser-matching rule was never harvested | escapes are decoded per §4.3.7 and compared against the attribute value a browser compares against |

The general property: `preludeToBareSelectors` decides selector shape from **token structure**, so
a garbage span like CR-04's `xurl(a/*z*/b).legal` cannot even be constructed — comments and
function tokens are separate tokens, not text glued onto an ident.
</why_the_token_stream_closes_these>
