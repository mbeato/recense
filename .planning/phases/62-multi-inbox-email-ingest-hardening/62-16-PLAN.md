## Why a tokenizer, and why css-tree — measured during planning, not assumed

**1. css-tree 3.2.1's tokenizer agrees with §4.3 on every production behind the six bypasses.**
Ten productions were tokenized during planning and the streams inspected:

| Probe | Input | css-tree token stream | Verdict |
|---|---|---|---|
| VF-01 (§4.3.2) | `/* legacy IE hack */.hide-in-app{display:none}` | `Comment`, then `Delim(.) Ident(hide-in-app) {` | comment is a token; selector is clean |
| FB-01 (§4.3.5) | `.a{content:"x⏎.legal{display:none}` | `BadString("x⏎)` then `Delim(.) Ident(legal) { … }` | bad-string ends AT the newline; tokenizing resumes |
| CR-04 (§4.3.6) | `xurl(a/*z*/b).legal{display:none}` | `Function(xurl()` `Ident(a)` `Comment(/*z*/)` `Ident(b)` `)` … | `/*z*/` IS a comment inside a non-`url` function |
| §4.3.6 positive | `url(/*notacomment*/x)` | single `Url` token | correctly NOT a comment here |
| §4.3.6 case/ws | `URL(/*x*/y)`, `url(  /*x*/y  )` | single `Url` token each | case-insensitive + whitespace correct |
| §4.3.6 quoted | `url("/*x*/")` | `Function(url()` `String` `)` | quoted form is function+string |
| §4.3.7 | `.a\/*b{q:1}` | `Delim(.) Ident(a\/) Delim(*) Ident(b) {` | identity escape consumes the `/` |
| §4.3.7 invalid | `\⏎/*c*/` | `Delim(\) WhiteSpace Comment` | `\`+newline is not an escape |
| §4.3.14 | `url(zzz}.legal{display:none}` | one `Url` token to EOF | matches the spec's EOF branch |
| §4.3.3/§4.3.4 | `#legal`, `@media` | `Hash`, `AtKeyword` | correct |

**2. postcss is DISQUALIFIED as an oracle — measured, not inherited.** It is wrong on exactly the
two inputs at issue: the FB-01 shape makes it **throw** `CssSyntaxError: Unclosed string` (it does
not error-recover the way §4.3.5 requires), and on the CR-04 shape it reports the selector as
`"xurl(a/*z*/b).legal"` — i.e. it reproduces CR-04's own reading. It is also only present
transitively (vitest → vite → postcss@8.5.15), never declared. It is used nowhere in this plan set.

**3. A §4.3 transcription was rejected on the burden-of-proof test.** With postcss disqualified,
a transcription's conformance could rest only on a hand-derived closure argument — exactly what
`stripCssComments`'s doc comment already claims and exactly what CR-04 attacked from *inside* a
production the enumeration listed correctly. A seventh hand-rolled scanner with no better oracle
than the sixth had is a repetition, not a plan.

**4. Cost is strictly linear.** Measured at the 1 MiB cap boundary across nine adversarial CSS
shapes: 2.6-11.4 ms (brace-free `a<x ` 11.4; `/*y` 2.6; `url(z` 3.3; `"x⏎` 3.6; `\a` 4.6;
alternating quotes 5.9; real rules 6.0; `{` repeated 5.4; `xurl(` repeated 5.1). Single forward
pass, no backtracking. The pre-62-14 module cost 126,422 ms on the report's shape.

**5. Dependency surface, stated plainly.**
  - `require('css-tree/tokenizer')` loads **8 files / 56,241 bytes and pulls in ZERO transitive
    packages** (verified via `require.cache`); `mdn-data` and `source-map-js` are declared deps of
    the full package but are unreachable from that entry point.
  - `npm install` footprint is nonetheless **2.9 MB on disk** (css-tree 2.0 MB + mdn-data 776 KB +
    source-map-js 180 KB). Stated rather than hidden behind the 56 KB runtime figure.
  - Production dependencies go from 8 to 9 in a deliberately lean project. The stripper runs in the
    **offline** ingest path, not the latency-sensitive online retrieval path, so `CLAUDE.md`'s
    "online paths stay LLM-free and fast" constraint is untouched: no LLM, no I/O, no clock read.
  - css-tree ships **no types**, and `@types/css-tree@2.3.11` **does not declare the
    `css-tree/tokenizer` subpath** (verified: `tsc` still fails TS7016 with it installed). A 7-line
    local ambient declaration resolves cleanly under `moduleResolution: "bundler"` + `strict: true`
    and pins the exact API surface. `@types/css-tree` is deliberately NOT added.

**6. What is adopted where.**
  - **Production (`src/`)**: only `css-tree/tokenizer` — `tokenize(source, onToken)` and
    `tokenTypes`. The parser, lexer, walker, generator and `mdn-data` must never be imported from
    `src/`; the ambient declaration enforces this by declaring only that subpath.
  - **Tests only (`tests/`)**: the css-tree **parser** is used to build the liveness oracle
    (Task 3). This is a test-time ground-truth source, never shipped, never on the ingest path.
    It is a genuinely different code path from the token walk 62-17 will write — it implements the
    §5.4 parse layer and selector validity that recense hand-rolls — while sharing the tokenizer,
    whose conformance Task 2 independently gates against the spec.

**7. Two characterized css-tree deviations** (found by fuzzing 300,000 hostile inputs during
planning; neither is a §4.3 violation, both are locked because a future upgrade that changed them
would silently break offset arithmetic): a leading U+FEFF BOM is **skipped** (first token starts at
offset 1), and an unterminated construct ending in a trailing backslash can emit an end offset of
**exactly `source.length + 1`** (max overrun 1, over 300k inputs). Totality holds: **0 throws over
20,018 hostile inputs** including lone surrogates and NUL.

<adjudication_from_planning>
## The finding that reshaped this plan set: both chartered blockers are non-defects, and three unfiled leaks are real

Planning built a throwaway liveness oracle (css-tree's §5.4 parser + selector parser) and ran every
open finding through it, then ran the same inputs through the **built `dist/`**. Read the last
column, not the first.

| Input | Conformant CSS engine | shipped `dist/` | Adjudication |
|---|---|---|---|
| **FB-01** `.a{content:"x⏎.legal{display:none}` | **NOT LIVE** — only rule parsed is `.a`; `.legal{display:none}` is consumed inside `.a`'s unterminated declaration block (§5.4.4 / remnants-of-a-bad-declaration), so no `.legal` rule exists | payload present | **AGREEMENT — not a leak** |
| **CR-04 shape 1** `xurl(z/* … */.hide-in-app{display:none}` | **NOT LIVE** — no rule at all; the unterminated function block runs to EOF | payload present | **AGREEMENT — not a leak** |
| **CR-04 shape 2** `xurl(a/*z*/b).legal{display:none}` | **NOT LIVE** — one rule whose prelude is `xurl(a/*z*/b).legal`, an invalid selector, so the rule is dropped | payload present | **AGREEMENT — not a leak** |
| FB-01 rebalanced control `.a{content:"x⏎}.legal{…}` | LIVE (`.a`, `.legal`) | stripped | correct |
| CR-04 declaration-position variant `.a{background:xurl(a/*z*/b)}.legal{…}` | LIVE (`.legal`) | stripped | correct |
| VF-01, all three shapes | LIVE | stripped | correct — VF-01 *was* a genuine leak, correctly closed |
| **`.leg\61 l{display:none}` vs `class="legal"`** | **LIVE** — a CSS escape in a class name is unescaped for matching | **payload present** | **GENUINE LEAK, never filed** |
| **`.leg\al{display:none}` vs `class="legal"`** | **LIVE** | **payload present** | **GENUINE LEAK, never filed** |
| **`#leg\61 l{display:none}` vs `id="legal"`** | **LIVE** | **payload present** | **GENUINE LEAK, never filed** |

Interpretation, stated carefully because the burden of proof is on the party contradicting a filed
blocker:

- The reviewer's CR-04 analysis of the *token-boundary defect* is correct — `matchesUrlOpen` really
  does lack a boundary check. What does not follow is the security consequence. Whenever the false
  raw span covers a comment, that comment sits inside a parenthesised function; in prelude position
  that makes the selector invalid (so a browser drops the rule too), and in declaration position it
  cannot affect any selector. A browser therefore shows the payload as well, so passing it to the
  extractor is correct behavior, not an EchoLeak vector.
- The verifier's FB-01 analysis assumed tokenizing resumes *at top level* after a bad-string. It
  resumes, but at nesting depth 1, inside the still-open `.a{` block. The rule never reaches top
  level, so the browser does not apply it either.
- Neither of these is a criticism of the reports: both correctly identified real divergences from
  §4.3. What was missing on both sides — filer and implementer — is the layer above the tokenizer,
  where liveness is actually decided. That is precisely WR-09's point, and it is why this plan
  builds the oracle before anything else changes.

**This adjudication is not accepted on planning's authority.** Task 3 requires the executor to
re-derive every row independently and ship it as an assertion, and Task 4 puts the disposition in
front of the operator. If the executor's re-derivation contradicts this table, the executor's
measurement wins and Task 4 reports that instead.
</adjudication_from_planning>
