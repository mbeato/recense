<interfaces>
Define these FIRST, in `src/source/strip-hidden.ts`, before wiring anything — plan 62-24 consumes
`startTags` and must not have to rediscover the shape:

  interface HtmlComment  { start: number; end: number }            // [start, end) over the input
  interface HtmlStyleElement { contentStart: number; contentEnd: number; elementEnd: number }
  interface HtmlStartTag {
    name: string;                       // lowercased
    attrs: ReadonlyMap<string, string>; // lowercased name -> DECODED value (CR-07, wired in 62-24)
    tagStart: number;                   // index of '<'
    tagEnd: number;                     // index just past '>'
    elementEnd: number;                 // index just past the element's end (or input length)
  }
  interface HtmlScan {
    comments: readonly HtmlComment[];
    styleElements: readonly HtmlStyleElement[];
    startTags: readonly HtmlStartTag[];
  }
  function scanHtml(html: string): HtmlScan

THIS PLAN wires `comments` (stage 3) and `styleElements` (stage 2) only. `startTags` is produced and
unit-tested here but not yet consumed by stages 4/5 — plan 62-24 owns that rewiring. Producing it now
is deliberate: it is the contract 62-24 builds against, and defining it in the same pass that
establishes the parser's offset arithmetic avoids two different readings of the same event stream.

Parser API surface, offset inclusivity and characterized deviations: read
`62-21-SUMMARY.md` — do not re-derive them.
</interfaces>

<what_must_not_change>
The module is a range-deleting transformer. `scanHtml` produces RANGES; it never produces text.
There is no serialization step, no tree walk that emits content, and no entity decoding applied to
prose. Both documented contracts depend on this:
  - idempotence: `stripHiddenContent(stripHiddenContent(x)) === stripHiddenContent(x)`
  - "every entity except `&nbsp;`/`&#160;` is left literal" (stage 7)
A parse-then-serialize design breaks both (`&amp;amp;` -> `&amp;` -> `&` across passes) and is out of
bounds for this plan regardless of how much simpler it looks.

Stage 0's hoisted stray-`<` truncation and stage 6's `ANY_TAG_RE` sweep remain hand-rolled after this
plan. That is a named residual, not an oversight — say so in the SUMMARY and in the file-level doc
block, and name plan 62-24 as the owner of the stage-4/5 half.
</what_must_not_change>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| attacker-authored HTML -> `scanHtml` | The adversary authors markup specifically to make a scanner disagree with a browser about where a comment or a RAWTEXT element begins |
| `scanHtml` ranges -> stage 2 / stage 3 deletions | A wrong range either leaks hidden content or destroys visible prose; both directions are in scope |
| body size -> ingest CPU | A new parser on the online ingest path re-opens the availability question the 1 MiB cap answers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-22-01 | Information disclosure | `<style>` inside an HTML comment hijacking stage 2 (CR-10) | mitigate | Comment-vs-element is decided once by the adopted parser; stage 2 iterates `scan.styleElements`, which structurally cannot contain a commented-out `<style>` |
| T-62-22-02 | Information disclosure | fail-open scan on parser error | mitigate | A parser-internal error returns the maximally-reducing scan, never an empty one; asserted by a forced-error test |
| T-62-22-03 | Denial of service | stage 3's unterminated-comment truncation destroying the document (NF-01) | mitigate | The parser reports an unterminated comment's real extent, so the truncation fail-safe is deleted rather than kept as a blunt instrument |
| T-62-22-04 | Denial of service | parser cost at the ingest boundary | mitigate | Task 3 re-derives the cap against >= 29 shapes at exactly 1,048,576 code units, with a shipped cost-regression test |
| T-62-22-05 | Tampering | idempotence / entity-literal contract broken by a parse-then-serialize design | mitigate | `scanHtml` returns ranges only; no serialization; existing idempotence tests plus an explicit `&amp;amp;` assertion |
| T-62-22-06 | Repudiation | an expected-failure silently flipping | mitigate | Every `it.fails` that now passes is converted deliberately and listed; deleting a lock to go green is forbidden |
</threat_model>
