<objective>
Ship `recense gmail-auth <account-id>`: a guided CLI that mints a Gmail refresh token for an
additional Google account via a loopback OAuth redirect and stores it — plus the account
registration — in `~/.config/recense/sleep.env`, with no hand-rolled OAuth and no hand-edited files.

Purpose: EMAIL-01. Multi-account Gmail fan-out already ships (v4.0 TEMP-04, D-08/D-09/D-10) and plan
62-01 made a second account reachable from config. The missing piece is the onboarding path: today
minting `GOOGLE_WORK_REFRESH_TOKEN` means running someone else's OAuth snippet and pasting the result
into a chmod-600 env file by hand. This is also the single most credential-sensitive surface in the
phase — a long-lived refresh token is written to disk, and the redirect catcher is a real local
listener — so the threat model here is load-bearing, not boilerplate.

Output: one new CLI module with a testable pure-helper core, one dispatcher case, and two test files
covering the helpers and the live loopback catcher. Zero new runtime dependencies: `node:http`,
`node:crypto`, and the existing `googleapis` OAuth2 primitives only.
</objective>

— parse with `new URL(rawUrl, 'http://127.0.0.1')`. Order of checks: an `error` query param returns
`denied`; a missing `state` returns `state_missing`; a `state` that does not match returns
`state_mismatch`; a missing or empty `code` returns `code_missing`; otherwise `ok` with the code.

first (`timingSafeEqual` throws on length mismatch), and treat a length mismatch as `state_mismatch`.
Fail closed on every ambiguity; never return `ok` with a code when state validation did not pass.

— create a `node:http` server, `listen(0, '127.0.0.1')` (host argument is mandatory: binding
`0.0.0.0` would expose the authorization code catcher to the local network), resolve once `listening`
fires, and read the assigned port from `server.address()`. The request handler runs
`parseOAuthCallback(req.url ?? '', expectedState)`, writes a minimal `text/plain` body (a success
line, or a failure line naming the reason but never echoing any query value), sets status 200 on
success and 400 on any failure, settles the `result` promise with that outcome, and then closes the
server. Arm a `setTimeout(timeoutMs)` that settles `result` with `{ ok: false, reason: 'timeout' }`
and closes the server; clear the timer on any settle. `close()` must be idempotent and must call
`server.closeAllConnections()` (or equivalent) before `server.close()` so a keep-alive browser socket
cannot hold the process open. The `result` promise must settle exactly once regardless of how many
requests arrive — a second request after settling gets a 400 and is otherwise ignored.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → loopback listener | Anything on the local host can connect to the ephemeral port while it is open. The request carries an OAuth authorization code that is exchangeable for a long-lived refresh token. |
| Google → CLI (token endpoint) | The token response contains a long-lived refresh token — the most sensitive value this phase handles. |
| CLI → disk (`sleep.env`) | A long-lived credential is persisted at rest in a file that other local processes could read if permissions are wrong. |
| CLI → stdout / `/tmp` log | Terminal output is routinely copy-pasted; `/tmp` logs are world-readable by default on many systems. |
| operator → argv | The account id becomes an env-var key name and an entry in a comma-separated list. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-07 | Spoofing | Loopback catcher network exposure | mitigate | `server.listen(0, '127.0.0.1')` — the host argument is mandatory and asserted by both a runtime test and a source assertion that `'0.0.0.0'` does not appear. Ephemeral port (0) means no predictable target across runs. |
| T-62-08 | Tampering | Authorization-code injection / CSRF on the redirect | mitigate | A 32-byte `randomBytes` `state` is minted per run, passed through `generateAuthUrl`, and compared in `parseOAuthCallback` with `crypto.timingSafeEqual` behind an equal-length guard. Any mismatch, absence, or length difference returns `state_mismatch`/`state_missing` and the code is NEVER exchanged. Tests assert `ok` is unreachable with a wrong state even when a valid-looking `code` is present. |
| T-62-09 | Denial of Service | Lingering listener | mitigate | Bounded lifetime: a 300 s timer settles the result as `timeout` and closes the server. `close()` is idempotent, calls `closeAllConnections()` first so a keep-alive browser socket cannot pin the process, and runs in a `finally` so an exception on the exchange path still tears the listener down. A `timeoutMs: 50` test proves the port stops accepting. |
| T-62-10 | Information Disclosure | Refresh token at rest | mitigate | Persisted only via the existing `writeEnvFile`, which writes a tmp file with mode `0o600`, re-`chmod`s it belt-and-suspenders, and atomically renames it inside the destination directory. This plan adds no `writeFileSync` of its own; a test asserts the resulting file mode is `0o600`. |
| T-62-11 | Information Disclosure | Token / code / secret in stdout or logs | mitigate | Output and the `/tmp/recense-gmail-auth.log` carry env-var NAMES and single reason WORDS only. The raw callback URL is never echoed (it contains the code). A source-assertion test verifies no stdout or log call site interpolates `refreshToken`, `code`, or `clientSecret`. |
