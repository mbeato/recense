<why_the_old_oracles_could_not_work>
WR-09's three findings, restated as design constraints this plan must satisfy:

1. **The ground-truth-by-construction generator** (`tests/strip-hidden.test.ts:503-581`) draws every
   `url(` from `DECOY_FRAGMENTS`, which always writes it immediately after `background:` — a real
   token boundary — and only ever `.`-joins whole `.gdN{…}` rules. No generated stylesheet can
   place an ident-sequence character directly before `url(`. The generator's own doc comment
   concedes the class of limitation in the abstract; the fragment pool was never audited against
   its own stated risk. **Constraint: the generator's alphabet must not be derived from the case
   enumeration it validates.**

2. **The differential harnesses** (62-14, 55k + 80k inputs, scratch) compared two versions of the
   same `stripCssComments`, byte-identical across the diff — so a defect present on both sides
   produced zero differences at any corpus size. A differential validates "did this change
   anything," not "is this correct." **Constraint: correctness needs a judge that is not another
   copy of the code under test.**

3. **The deterministic fuzz test** (`tests/strip-hidden.test.ts:1054-1104`) has an alphabet
   containing both single letters and `url(` as independent randomly-placed pieces, so across 2,000
   iterations it almost certainly generated CR-04's `<letter>url(` adjacency — but it asserts only
   totality, idempotence and "no stray `<`". It had the raw material and was not looking for the
   right thing. **Constraint: the property asserted must be hidden-content leakage.**

62-16's `liveHidingSelectors` satisfies constraint 2: it is a conformant CSS engine's verdict, not
a second copy of recense's harvest. This plan supplies constraints 1 and 3.
</why_the_old_oracles_could_not_work>
