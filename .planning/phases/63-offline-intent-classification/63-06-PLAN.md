<objective>
Measure honestly what the enlarged gmail prompt prefix actually costs in input tokens, and record it. CLASSIFY-01's claim is "no net-new LLM call per episode" — plan 63-04 proves the call count; this plan quantifies the one thing a call-count sentinel cannot see: the prompt got bigger, and bigger prompts cost tokens.

Purpose: the project's hard rule is no inflated metrics, and Pitfall 15 explicitly requires measuring token cost the way Phase 42 did rather than asserting it. A zero-net-new-call claim published without the prefix delta beside it would be an unearned number.
Output: a measurement harness, a measured (or honestly marked unmeasured) figure, and a founder checkpoint on the number before it enters the phase record.
</objective>

- Report per-arm input tokens, absolute delta, percent delta relative to arm A, the model id used, and the constant-prefix character counts for both arms as a deterministic cross-check on the token figures.

- Emit a human-readable console report and a JSON blob at `scripts/eval/results/63-intent-prompt-token-delta.json` containing at minimum `measured`, `reason` (when unmeasured), `model`, `arm_a_input_tokens`, `arm_b_input_tokens`, `input_token_delta`, `input_token_delta_pct`, `arm_a_prefix_chars`, `arm_b_prefix_chars`, and `measured_at`.
- Never print or write a token number the sink did not produce. If the sink captured zero calls in live mode, emit `measured:false` with the reason and exit non-zero.

Header docblock must record: currency is tokens, any dollar figure is an API list-price equivalent (subscription marginal cost is ~$0 while token usage is real), and one full run costs exactly two `claude -p` calls.
