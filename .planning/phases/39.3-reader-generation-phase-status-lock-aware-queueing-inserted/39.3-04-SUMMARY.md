## What Was Built

**src/viz/modules/reader.js** — two logical changes:

**(1) startGenProgress(elapsedMs, initialPhase) — phase-aware stepper**
- Builds a `.doc-progress-steps` row containing 5 step elements + 4 connectors
- Each step has a label (textContent), a track, and a fill (all via textContent/DOM — T-39.3-08)
- Returns `{ stop, done, update(phase) }`:
  - `update(phase)` sets the new activePhase and re-renders step states without restarting the interval
  - `generating` step fill driven by the existing exponential TAU curve (GEN_ESTIMATE_MS/TAU)
  - all other steps: fill snaps to 100% when active or done
- Elapsed clock label below the stepper (same position as the old `.doc-progress-label`)

**(2) loadWithPoll 202-branch — phase/error handling**
- Parses full envelope: `j = await res.json()` (with fallback on parse error)
- If `j.phase === 'failed'`: stops the progress controller, renders `"generation failed: " + (j.error || 'engine stayed busy')` via textContent into the body, returns (stops polling) — T-39.3-08/T-39.3-09
- For non-failed phases: builds progress on first 202 (seeded from `j.elapsedMs`), then calls `progress.update(j.phase)` on subsequent polls

**(3) regenerate() cleanup (Task 2)**
- Deleted `const prevGeneratedAt = await fetchGeneratedAt()` capture and its comment block
- Deleted the `newGeneratedAt` comparison block and the generic 'timed out or errored' string
- Deleted the entire `fetchGeneratedAt()` function — zero callers remain
- `regenerate()` now: remove banner -> insert "regenerating doc..." -> POST -> reset state -> `await loadWithPoll()` -> catch (e) shows inline error

**src/viz/css/styles.css** — minimal stepper rules added (replacing the old single-bar rules):
- `.doc-progress-steps` — flex row
- `.doc-progress-step` — flex column per step
- `.doc-progress-step-label` — muted slate text (textContent)
- `.doc-progress-step-track` + `.doc-progress-step-fill` — narrow bar per step
- `.doc-progress-connector` — thin connector between steps
- `.doc-progress-step--active` — amber label + amber fill (Phase 34 guard: activation only)
- `.doc-progress-step--done` — muted rose label + rose fill
- `.doc-progress-label` — preserved for elapsed/ETA text below stepper
