<objective>
Add semantic phase EVENTS to the generator and turn the CLI's instant lock-bail into a real
wait-queue that reports phase. `doc-generator.ts` gains an optional `onPhase` callback (it stays
filesystem-free — it only emits events). `generate-doc-cli.ts` replaces the `acquireLock()`-or-exit-0
with a bounded wait loop (write 'queued', poll ~2s re-stamping 'queued', give up after the doc-gen
timeout budget → 'failed: engine stayed busy'), wires `onPhase → writeStatus`, and writes the
remaining transitions (finalizing, done+clearStatus, failed{error}).

Purpose: RGS-02 (lock contention becomes an honest wait + give-up, not a silent bail) and RGS-01/03
(the real pipeline phases reach the status file the server reads). lockfile.ts acquireLock() is
UNCHANGED — the loop lives in the CLI.

Output: doc-generator onPhase callbacks, CLI lock-wait + phase wiring, and a doc-generator test
asserting onPhase ordering.
