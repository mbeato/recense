<objective>
Extend the viz server's 202 envelope to forward the generator's real phase. `send202Generating`
calls `readStatus(slug)` (the read-only consumer of the status file the CLI writes) and builds the
body via the PURE `buildGeneratingEnvelope(status, elapsedMs)` helper (from gen-status.ts, Plan 01),
emitting `{ status:'generating', phase, elapsedMs, error? }`. `elapsedMs` still comes from the
in-flight Set as today. The server's only new dependencies are `readStatus` (filesystem read) and
`buildGeneratingEnvelope` (pure) — the DB handle stays read-only (T-27-11 preserved; no engine write,
no new node/edge types).

Purpose: RGS-01 (the named phase reaches the client) and RGS-03 (an authoritative failed phase
crosses the detached-child→read-only-server boundary so the reader can stop on a real failure
instead of the generated_at no-op hack).

Output: a modified `send202Generating` building the envelope via the pure helper, plus a unit test
(`tests/gen-envelope.test.ts`) proving phase/error forwarding and key-omission on null status.
</objective>
