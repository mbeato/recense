## What Was Built

### src/reader/doc-generator.ts

Added optional `onPhase?: (phase: string) => void` to the `opts` parameter object of both `generateDoc` and `generateDocForSchema`. Three fire sites per function, using optional-chaining call form:

- `opts.onPhase?.('gathering')` — immediately before `gatherFacts`/`gatherFactsForSchema` (step 1)
- `opts.onPhase?.('generating')` — immediately before `provider.generate()` (step 3)
- `opts.onPhase?.('verifying')` — immediately before `verifyCitations()` (step 4)

No filesystem import added. doc-generator stays FS-free (D-3 invariant).

### src/adapter/generate-doc-cli.ts

**Exported `waitForLock({ acquire, writeQueued, writeFailedBusy, sleep, now, budgetMs, pollMs })`:**
- Calls `writeQueued()` before each `acquire()` attempt to keep `updatedAt` fresh
- Returns `true` when lock acquired
- Returns `false` (after calling `writeFailedBusy()`) when elapsed >= budgetMs

**Full status lifecycle now wired:**
- `writeStatus(slug, 'queued')` — re-stamped per poll iteration in `waitForLock`
- `writeStatus(slug, 'failed', { error: 'engine stayed busy' })` — on lock budget expiry
- `onPhase -> writeStatus` — gathering/generating/verifying transition into status file
- `writeStatus(slug, 'finalizing')` — before `writeDoc` + `DocGraphDeriver` (step 8)
- `writeStatus(slug, 'done')` + `clearStatus(slug)` — after successful commit (step 9)
- `writeStatus(slug, 'failed', { error: String(err) })` — in `catch` before stderr
- `writeStatus(slug, 'done')` + `clearStatus(slug)` — in cached-hit early-return to prevent dangling 'queued'

**Timeout ordering fix:** env vars raised before `budgetMs` is read so the lock-wait inherits the same 600s headroom.

**lockfile.ts unchanged** — `acquireLock()` semantics are still non-blocking O_EXCL; the bounded wait loop lives entirely in the CLI.

### tests/generate-doc-cli.test.ts (new)

4 unit tests for `waitForLock`:
1. Returns true when acquire succeeds on first attempt
2. Polls until acquire succeeds, re-stamps queued on each iteration, sleeps between polls
3. Returns false and calls writeFailedBusy when budget expires
4. Does not call sleep after the final successful acquire
