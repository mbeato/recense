<objective>
Create the shared status-file module `src/adapter/gen-status.ts` — the single boundary
across which the detached `generate-doc` CLI (sole writer) reports generation phase to the
read-only viz server (reader-only). This module owns ALL filesystem access for generation
status; `doc-generator.ts` stays FS-free, and the viz server gains exactly one read-only
dependency (`readStatus`).

Purpose: Fix the lock-contention silent-bail (RGS-03) by giving the child a place to write
an authoritative phase the server can read back across the detached-process boundary,
preserving the T-27-11 read-only-server invariant (CLI writes, server reads).

Output: `src/adapter/gen-status.ts` with PHASES/statusPath/writeStatus/readStatus/clearStatus,
plus `tests/gen-status.test.ts` proving path-safety, round-trip, and staleness.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL slug → statusPath | A reader/HTTP-supplied slug reaches statusPath; untrusted string crosses into a filesystem path |
| detached child → read-only server | The CLI writes the status file; the server reads it — a process boundary, no shared memory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39.3-01 | Tampering | statusPath(slug) path construction | mitigate | Hash the slug (sha1.slice(0,16)) so no `/` or `..` survives into the path; tested with `../../etc/passwd` asserting containment under the status dir |
| T-39.3-02 | Information Disclosure | status JSON in world-readable /tmp | accept | Status contains only phase + timestamps + a fixed error string; no PII, no fact values, no secrets — same /tmp posture as the existing recense-generate-doc.log |
| T-39.3-03 | Denial of Service | stale file from a crashed child freezing the reader | mitigate | readStatus returns null past STALE_MS so a crashed child reads as absent; tested |
</threat_model>
