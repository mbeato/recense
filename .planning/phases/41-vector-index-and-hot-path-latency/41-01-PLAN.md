<objective>
Resolve the mechanism question (zero-dep flat `Float32Array` cache vs `sqlite-vec` `vec0` extension) on REAL numbers from the live ~11.3k-node brain BEFORE the implementation commits to a dependency. This is the load-bearing artifact of the phase (D-03/D-04/D-09).

Purpose: The Phase 40 baseline only measured WARM in-process retrieval (`live-latency.cjs` = 45/46 ms). It never measured the COLD path — process spawn + re-marshaling ~11k SQLite rows + allocating ~11k `Float32Array` views per invocation — which is the felt latency for SessionStart inject and `recall-cli`. The spike must add that cold measurement, since it is what exposes whether persistence (D-06) actually helps and which mechanism wins.

Output: An instrumented comparison harness (`scripts/eval/41-index-spike.cjs`) and a recorded decision (`41-SPIKE-FINDINGS.md`) that Plan 41-02 reads via `read_first`.

NOTE: This plan does NOT hardcode an outcome. Acceptance is that BOTH candidates are measured cold+warm vs the brute-force baseline and a decision is recorded with the numbers and the D-04 tie-break applied. "Zero-dep wins" and "sqlite-vec wins" are both valid outcomes.
</objective>
