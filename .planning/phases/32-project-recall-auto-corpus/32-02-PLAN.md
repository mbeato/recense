<objective>
Build the scope-anchored always-promote bypass (D-04) and the project landing doc (D-02) — the
mechanism that guarantees a freshly-onboarded project is fully browsable in the Reader without a
manual `recense generate-doc` step.

For a given project scope S the promoter must, in one atomic pass:
- identify S's induced schemas (schemas whose abstracted observed members carry node_scope = S),
- always-promote those schemas' chapter-doc stubs AND a project landing-doc stub (slug = S),
  bypassing the mass/noise gate ONLY for S,
- write doc_containment edges from the landing doc (parent) to each chapter doc (child) so the
  landing doc's links never dangle (D-05 discretion: containment is the landing→chapter edge model).

And the corpus generator must fill the landing-doc stub (slug = scope) via the project-scope
`generateDoc()` path, while continuing to fill schema-chapter stubs via the existing schema path.

CRITICAL bound (D-04): global and conversation-induced schemas keep the existing mass-hysteresis
gate completely unchanged — the bypass is onboarding-only and never promotes thin out-of-scope
schemas. This plan builds the API; Plan 32-03 wires the two trigger paths to it.

Purpose: satisfies SC2 (auto-promote + auto-generate after sleep pass) and SC3 (landing doc reads
as a coherent project overview anchored on the project's schemas with cited evidence).
Output: a `promoteScope(scope)` capability on CorpusPromoter + landing-doc generation routing.
</objective>
