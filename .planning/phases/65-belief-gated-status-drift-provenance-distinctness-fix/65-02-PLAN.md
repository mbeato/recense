<objective>
Build the D-06 quoted/forwarded-content detector: a pure, deterministic, LLM-free pair of functions that reduce an email body to the author's own newly-written text, and judge whether what remains is too small to count as independent evidence.

Purpose: this is the half of the DRIFT-03 fix that stops the obvious "fix" from becoming a farming vector. Research Pitfall 3 is explicit that keying distinctness on message identity turns three forwards of one thread into three "independent" corroborations, force-destabilizing a belief off a single underlying claim. Stripping quoted/forwarded content before keying is what makes 3-forwards count as 1.
Output: `src/source/strip-quoted.ts` and a table-driven unit suite.

**Not in this plan:** no key composition (65-04), no adapter call site (65-06), no config wiring. This module is standalone and directly unit-tested with plain strings.

**Placement note (planner discretion, CONTEXT `## Claude's Discretion` — "Module placement/naming for the quote-stripper"):** 65-PATTERNS.md sketched `src/consolidation/strip-quoted.ts`. It ships at `src/source/strip-quoted.ts` instead, as a sibling of its analog `strip-hidden.ts`. Reason: the distinctness key must be derived at INGEST, because Gmail's `threadId` never reaches `episode.content` and therefore cannot be recovered consolidation-side. A `src/consolidation/` module imported by `src/source/gmail-adapter.ts` would invert the dependency direction for no benefit. The substantive D-06 constraint is preserved exactly: this stripper runs on the provenance/distinctness path ONLY and never touches `record.content`, the extractor's input, or Phase 62's EMAIL-03 stripping.
</objective>

Create `src/source/strip-quoted.ts` exporting exactly two functions: `stripQuotedForwarded(text: string): string` and `isNearEmptyResidual(text: string, minNonWhitespaceChars: number): boolean`. Keep them separate — do NOT fold the emptiness judgement into the stripper. This mirrors `stripInvisibleCodepoints` staying separate from `stripHiddenContent`, and it matters here because Plan 65-10's dry-run harness needs to report the residual-length distribution independently of the pass/fail judgement so the threshold can be tuned against real inbox data.

**Compile every pattern once at module scope** as `const <NAME>_RE = /.../<flags>;` — never inside a function body. Name them explicitly so the test and future readers can find them:

  - `QUOTE_LINE_RE` — a line whose first non-space character is `>` (allow up to 3 leading spaces before the `>`, matching the common mailer soft-wrap). Multiline.
  - `ATTRIBUTION_RE` — the `On <anything> wrote:` boundary. Must tolerate the line wrapping that real mailers insert, i.e. match `On` at a line start followed by up to ~200 characters (possibly spanning one newline) ending in `wrote:`. Bound the span explicitly with a length-limited character class rather than a greedy `.*` — an unbounded greedy match across a 2 MB body is the classic catastrophic-backtracking foot-gun and this function must be total.
  - `FORWARD_MARKER_RE` — forwarded-message banners at line start. Cover at minimum: `---------- Forwarded message ----------` (any run of 2+ dashes on each side), `-----Original Message-----`, and `Begin forwarded message:`.
  - `SIGNATURE_DELIM_RE` — the RFC 3676 `-- ` sig delimiter on its own line. Treat everything from it onward as non-independent content, same as a quote.
  - `NON_WHITESPACE_RE` — used by `isNearEmptyResidual` for the non-whitespace count.

**`stripQuotedForwarded` algorithm** (single pass, deterministic, no clock, no I/O, no randomness):
  1. Guard the input size first, mirroring the `MAX_STRIP_INPUT_CODE_UNITS` fail-closed precedent: declare a module constant `MAX_QUOTE_STRIP_CODE_UNITS = 200_000` and, above it, return `''`. Returning EMPTY (not the input) is the fail-closed direction here — an oversized body yields "no independent residual", which under-counts provenance. Under-counting holds a belief longer; over-counting is the farming vector this module exists to prevent. State that reasoning in a comment at the constant.
  2. Split on `\n`. Walk the lines from the top and stop at the FIRST line matching `ATTRIBUTION_RE`, `FORWARD_MARKER_RE`, or `SIGNATURE_DELIM_RE` — everything from that line onward is dropped.
  3. From the surviving prefix, drop every line matching `QUOTE_LINE_RE`.
  4. Rejoin with `\n`, collapse runs of 3+ blank lines to one, and `.trim()` the result.

  The "stop at the first boundary" rule is deliberate and must be stated in a comment: quoted material below an attribution line frequently contains the ORIGINAL sender's un-prefixed text (Gmail's HTML-to-text conversion often drops `>` prefixes), so a quote-line-only filter would leak the quoted body through and defeat D-07.

**`isNearEmptyResidual(text, minNonWhitespaceChars)`** — count the characters in `text` that are not whitespace and return `count < minNonWhitespaceChars`. With `minNonWhitespaceChars = 0` this returns `false` for every input, which is the documented "gate disabled" value. The threshold is supplied by the caller (it comes from `config.provenanceMinResidualChars`, added in Plan 65-03) — this module holds no default and reads no config, so it stays trivially testable and sweepable by the dry-run harness.

**File header** must carry, in `strip-hidden.ts`'s style:
  - What it is: the D-06 quoted/forwarded detector for DRIFT-03.
  - The four-guarantee contract block, adapted verbatim in spirit from `strip-hidden.ts:124-130`: **Pure** (no side effects, no I/O, no randomness, no clock read), **Idempotent**, **Total** (never throws for any string, including empty/malformed/unterminated/adversarially-nested input), **Monotone toward less content** (output is always a subset-shaped reduction of the input; never the raw input re-expanded).
  - A **scope fence** stating in bold that this module is on the provenance/distinctness path ONLY: it must never be called from `normalizeGmailMessage`'s content path, never from `src/ingest/pipeline.ts`, and never in a way that changes `record.content`, the extractor's input, or Phase 62's EMAIL-03 `stripHiddenContent` behavior. Adding a second call site that feeds episode content is a correctness regression, not a refactor.
  - The under-count-over-count asymmetry: every ambiguous case resolves toward LESS residual, because under-counting provenance only delays a belief update while over-counting manufactures false independence (research Pitfall 3).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email body text → `stripQuotedForwarded` | The body is 100% sender-controlled, arbitrary-length, arbitrary-encoding UTF-8 derived from untrusted external email. It reaches this function verbatim from the Gmail API. |
| residual → provenance-distinctness key | Whether the residual is judged independent decides whether a message contributes a distinct provenance, which decides whether `contradictionN` is reached, which decides whether a belief is force-destabilized. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-02-FARM | Tampering | `stripQuotedForwarded` residual leakage | mitigate | Boundary-first algorithm (stop at the first attribution/forward/signature line) rather than quote-line filtering alone, precisely because Gmail's HTML-to-text conversion frequently drops `>` prefixes on quoted material. Proven by the Outlook-style fixture whose original body has no `>` prefixes at all. Every ambiguous case resolves toward LESS residual. |
| T-65-02-DOS | Denial of Service | `ATTRIBUTION_RE` catastrophic backtracking | mitigate | The attribution span is bounded by an explicit length-limited character class, never a greedy `.*`. Inputs above `MAX_QUOTE_STRIP_CODE_UNITS` (200,000 code units) short-circuit to `''` before any regex runs, mirroring the shipped `MAX_STRIP_INPUT_CODE_UNITS` fail-closed precedent in `gmail-adapter.ts`. A 2 MB wall-clock-bounded test case is the shipped regression guard. |
| T-65-02-EVADE | Tampering | Marker evasion to inflate residual | accept | A sender can always write genuinely new prose to earn an independent provenance — that is the intended behavior, not an attack. What the module must prevent is the same content counting N times, and that is closed by the boundary rule plus the `(sender-domain, thread-id)` key in Plan 65-04: evading the marker still yields the same domain and the same thread id, so the key collapses regardless. |
| T-65-02-UNI | Tampering | Invisible codepoints / RFC 2047 encoding used to break marker matching | transfer | Body text reaching this module has already passed `stripHiddenContent` at the adapter boundary (EMAIL-03, Phase 62). Sender identity — the other key component — gets `stripInvisibleCodepoints` in Plan 65-04 before parsing. This module does not re-implement either; it inherits them by call-site position. |
| T-65-SC | Tampering | npm/pip/cargo installs | N/A | Zero package installs. This module has zero imports and the test suite imports only `vitest` and the module under test. Net-zero new runtime dependencies invariant holds. |
