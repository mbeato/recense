<objective>
Build the belief-gated status-drift layer: a standalone, read-only, LLM-free decision module that consumes Phase 63's coarse intent confidence as a **dampener only** (D-09) and consults `event_ts` ordering before a contradicting claim reaches routing (D-11b) — without modifying `routeContradiction`, `isOscillation`, the PE bands, or the data model.

Purpose: DRIFT-01's whole point is that the status lifecycle rides the existing machinery **unmodified**. This module is how lifecycle-shaped judgement gets applied without touching the machinery: it sits structurally BEFORE the routing call and can only weaken, hold, or drop a contradiction. It also exports the emission-eligibility predicate that makes DRIFT-02's "a held update produces nothing downstream" structurally true before Phase 66's sink exists.
Output: `src/consolidation/status-drift.ts` and a unit suite covering damping, staleness, and all five structural guarantees.

**Not in this plan:** no consolidator wiring (65-08), no `ClaimDecision` fields, no counters in the sleep pass, no sink. This module is standalone and directly unit-tested against an in-memory SQLite DB.

**Placement (planner discretion, CONTEXT `## Claude's Discretion` — "whether the drift logic is a standalone module or a consolidator branch"):** standalone module, mirroring Phase 64's `entity-resolution.ts` D-01 precedent that CONTEXT names as the seam to mirror. Inlining it into `consolidator.ts` would put the DRIFT-01 "machinery unmodified" guarantee inside the same 1600-line file as the machinery, where a read-only/no-LLM/no-lattice guard cannot be asserted at file granularity.
</objective>
