`~/.claude/projects/*/memory/*.md` recall-facts into recense via the existing ingestion

### Design highlights

- **Reuses the pipeline (D-S4):** `runImport` calls `IngestionPipeline.recordEvent({content,
  role:'user', origin:'asserted_by_user', source:'memory-import', cwd, externalId})` — one
  episode per fact file. No new ingestion engine; consolidation derives scope from the
  mapped `cwd` per D-S3.
- **Idempotency (T-S4-02):** `external_id = memory-import:<project>:<filename>` is stable,
  so the `(source, external_id)` dedup backstop (D-59) makes a second run land zero new
  episodes. Proven by a test that runs the import twice and asserts the store still holds
  exactly 2 rows.
- **Skiplist (D-S5 / T-S4-03):** `MEMORY.md` (exact filename) → `memory-index`; the 7
  policy-bundle stems → `policy-bundle`; everything else imports. `resume` → `global` scope.
- **Dry-run is side-effect-free:** `planImport` reads the filesystem only — no DB open, no
  lock, no writes — so `--dry-run` is safe and is the single source of truth for what a
  real run does.
- **Never mutates sources:** the tool only reads fact files; deletion/retirement is a
  separate human step (D-S7). A test asserts file content + mtime are unchanged after a run.
- **Net-zero new deps:** `fs`/`path`/`os` built-ins only.
