# Phase 999.3 — Context: Scope-aware provenance + memory importer

Drafted 2026-06-16 (plan-now / execute-after-Phase-23). Part of the knowledge-consolidation initiative — see `~/.claude/projects/-Users-vtx-brain-memory/memory/consolidate-knowledge-into-recense.md`.

## Why
recense is meant to be Max's single foundational memory, but facts live in 4+ stores (recense, `~/.claude/projects/*/memory` MEMORY.md system, `~/vault`, `~/research`). The MEMORY.md per-project fact files are the redundancy recense was meant to replace. To migrate them in cleanly we need each fact to carry **which project it came from**, and a repeatable importer.

## Locked decisions
- **D-S1 — Provenance, not tenancy.** `scope` = single-tenant attribution of which project a fact originated in. Retrieval stays GLOBAL (semantic + recall floor already suppress most cross-project bleed; global recall is *wanted* — personal facts like voice/no-inflated-metrics and learned patterns must surface everywhere). This explicitly does NOT implement multi-tenant namespaces (v4.0 ROADMAP "Out of Scope: Multi-tenant namespaces — engine stays single-tenant"). `scope` is the provenance primitive, not an isolation boundary.
- **D-S2 — Sidecar, not a node column.** Store scope in a sparse sidecar table `node_scope` keyed by `node_id`. The `node` table stays the pure belief record (faithfulness). Follows the `node_temporal` / `activation_trace` / `consolidation_event` precedent (D-01). NO `ALTER TABLE node`.
- **D-S3 — Derive from cwd at consolidation.** Episodes already capture `cwd` (`src/ingest/pipeline.ts:87`, `turn-capture-cli.ts:86`). The consolidator (`src/consolidation/run-sleep-pass.ts`) resolves a node's scope from the `cwd` of its contributing episode(s): single known project → that slug; multiple distinct projects OR personal/home/unknown cwd → `global`.
- **D-S4 — Importer reuses the pipeline.** No new ingestion engine. `recense import-memory` creates episodes via `IngestionPipeline.recordEvent()` with `cwd` = the source project's path, `source='memory-import'`, and a stable `external_id` (file path or content hash) for idempotent re-runs. Normal consolidation then assigns scope per D-S3.
- **D-S5 — Migrate recall-facts only.** Skip load-bearing policy bundles (voice_profile, feedback_no_inflated_metrics, feedback_drop_concentrations, outreach_framework, user_job_search_strategy, reference_linkedin_playbook, user_profile) and `MEMORY.md` index files. Those stay deterministic config (retrieval is probabilistic; never risk dropping a load-bearing rule).
- **D-S6 — Surface scope, defer boost.** Recall output (`ambient-recall.ts buildHookOutput`, `session-start-cli`) prefixes facts with `[scope]`. A soft current-cwd relevance boost at recall is DEFERRED to a later phase (the recall hook already has cwd; revisit only if bleed proves real). No hard project filtering.
- **D-S7 — consolidate → verify → retire.** Never delete a `projects/*/memory` source file until its facts are verified retrievable in recense. Migration produces a verification report; retirement is a separate, human-confirmed step.

## cwd → scope mapping
- Map by the project directory basename of the cwd (e.g. `/Users/vtx/VTX` → `vtx`, `/Users/vtx/brain-memory` → `brain-memory`).
- Personal/non-project origins → `global`: the resume project (`-Users-vtx-resume`), home dir, empty cwd, or any cwd not matching a known project root.
- For the importer, the source folder name encodes the project: `~/.claude/projects/-Users-vtx-<slug>/memory` → cwd `/Users/vtx/<slug>` → scope `<slug>` (resume → `global`).
