<objective>
Open two opt-in seams in `retrieveRanked` — an entity-anchored candidate union and a 1-hop
edge hand-off — and make `buildHonestOneHopTrace` carry the relation predicate, without
changing a single byte of behavior for any existing caller.

Purpose: RECALL-01 needs anchored candidates to travel through the SAME floor/stale-entity/viz
machinery as cosine hits rather than around it, and RECALL-03 needs the edges the engine already
computes for the viz — D-06 forbids a second edge-read pass, so the engine must hand them out
rather than the adapter re-reading them.

Output: two new optional `opts` fields on `retrieveRanked`, an additive `rel` on honest-trace
hops with a sink-shape strip at every existing consumer, and the tests that lock all of it.
</objective>

## Trust Boundaries

| engine → activation_trace / viz SSE | Persisted + streamed payload consumed by a separate readonly process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-69-02-BYPASS | Elevation of Privilege | anchored union vs B2 stale-entity filter | mitigate | Anchored ids are checked against the SAME `staleEntityIds` Set and the same `tombstoned` liveness guard as cosine hits; only the cosine FLOOR is bypassed. Test-locked (Task 3). |
| T-69-02-FAKE | Repudiation | anchored row scoring | mitigate | Score is a real `cosineSimF32` over the stored embedding, clamped to [0,1]; unusable embedding → `0`, never a synthesized magnitude (WR-02 lineage, no-inflated-metrics). |
| T-69-02-SINK | Tampering | activation_trace payload drift | mitigate | Hops are projected to the pre-phase 4-key shape at every existing emit site; a key-set assertion locks it (D-06). |
| T-69-02-DOS | Denial of Service | hop pass over a widened seed set | accept | Seed union is bounded by `max(k,6)` viz seeds + returned rows + a defensive `slice(0,16)` on anchoredIds → worst case ~16 indexed `getOutEdgesWithRel` reads vs 6 today. Bounded, indexed, and measured in 69-06's latency probe; no unbounded fan-out is introduced. |
| T-69-02-SQLI | Tampering | anchored ids reaching SQL | mitigate | Ids are used only as bound params through `store.getNode` prepared statements; no interpolation, no new SQL in this plan. |
| T-69-02-FAILOPEN | Denial of Service | collector throw on the hook path | mitigate | The collector call lives inside the existing fire-and-forget `catch {}` — a consumer failure can never surface to the hook (T-10-05 precedent). |
| T-69-SC | Tampering | package installs | mitigate | No installs. Net-zero new runtime dependencies. |
</threat_model>
