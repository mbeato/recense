<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → `recense serve` (HTTP) | The adapter holds a long-lived Bearer token and crosses the network with it on every call |
| `recense serve` → adapter (response bodies) | Proposal records carry `evidence_quote` and `change_from`, which are free text derived from attacker-controllable email content |
| adapter → local store file | The store file is on-disk state that survives restarts and drives the "already applied?" decision |
| environment → adapter config | `RECENSE_*` env vars are the sole configuration surface; absence must fail closed, not open |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Information disclosure | `config.ts` / `proposal-client.ts` (serve Bearer token) | mitigate | Token is read from env only, held in a closure-scope `authHeader` string built once at factory scope (telegram precedent, memory-client.ts:106); never logged, never included in an error message, never persisted to the local store or any file |
| T-67-02 | Tampering (prompt/content injection) | `local-store.ts` `LocalRow` | mitigate | `evidence_quote` and `change_from` are never persisted and never interpolated anywhere; only closed-vocabulary/structured fields (`changeField`, `changeTo`, `entityDescriptor`) enter the local row. Quote is data, per 66's D-12 / this phase's D-07 |
| T-67-03 | Tampering | `local-store.ts` (store-file poisoning → duplicate apply) | mitigate | `putLocalRow` replaces by `localId`; `findByProposalId` gives the caller a pre-insert idempotency check keyed on the recense proposal id (D-02); `listLocalRows` shape-validates every field and returns `[]` on any parse/shape failure rather than trusting the file |
| T-67-04 | Information disclosure | local store file on disk | mitigate | Atomic tmp→rename write with `{ mode: 0o600 }` plus an explicit `chmodSync(0o600)` against umask, in the destination directory (EXDEV-safe) — telegram `proposal-store.ts:87-99` precedent |
| T-67-05 | Elevation of privilege | `config.ts` `enabled` gate | mitigate | `enabled = serveToken !== ''`; a missing token disables the adapter before any network call. Process-not-running is not the gate (docs/reference-client.md:239 discipline) |
| T-67-06 | Denial of service | `proposal-client.ts` | mitigate | `AbortSignal.timeout(10_000)` on every request; no query params added to `GET /v1/proposals`, so the server-side `PROPOSAL_LIST_LIMIT = 100` bound holds |
| T-67-07 | Spoofing | `clients/proposal-reference/` → `src/` | mitigate | Compile boundary (no `paths`/`references`) plus the static-scan sibling guard test wired into `npm test` — an engine import cannot land silently (CONSUME-02, D-04) |
| T-67-SC | Tampering | npm installs | accept | This plan adds ZERO package-manager installs — the net-zero-new-runtime-dependency invariant holds (`node:*` built-ins only; `better-sqlite3` deliberately not used, JSON store chosen per D-02). `git diff package-lock.json` must be empty; no legitimacy checkpoint is required because no package is introduced |
</threat_model>
