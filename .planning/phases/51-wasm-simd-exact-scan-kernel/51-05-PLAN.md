<objective>
Close WR-01 / SC2 — the equivalence proof. The kernel accumulates cosine entirely in f32 (f32x4 lanes → f32 horizontal sum → f32 reciprocal-norm multiply) while both the scalar fallback and the brute-force `cosineSimF32` reference accumulate in f64. This is a precision-CLASS difference, not sum-reordering. At dim=1536 the worst-case f32 dot error (~sqrt(384)·2⁻²⁴ ≈ 1–3e-6) can meet or exceed the gate's TIE_EPS=1e-6. The existing gate proved equivalence on 20 SEEDED MOCK unit-vectors only — under-powered for the production worst case, leaving SC2 UNCERTAIN.

This plan hardens `scripts/eval/51-topk-equivalence.cjs` so a `--real-embed` run produces DEFENSIBLE evidence, then runs it on the live brain to make SC2 true (or to surface a genuine finding):

1. Fix the inaccurate TIE_EPS comment (lines ~56-58) that misattributes divergence to "sum-order difference" — the real source is the f32-vs-f64 precision class.
2. Make the `--real-embed` path FAIL LOUD when real embeddings are unavailable/degenerate (missing OPENAI_API_KEY, zero/NaN vectors) — never vacuously pass. Per project memory, manual recense runs that lack OPENAI_API_KEY otherwise fail silently/masked.
3. Promote the existing informational `max|Δscore|` into a HARD budget assertion so a run approaching TIE_EPS fails the gate.
4. Add an explicit recall@10 metric so SC2's "recall@10 = 1.000" claim is measured, not inferred.
5. Human-verify: run `--real-embed` on the live brain, record the empirical max|Δscore| and recall@10. If max|Δscore| approaches/exceeds 1e-6, recalibrate TIE_EPS to the empirical bound AND document it as a finding — do NOT widen the epsilon merely to pass (hard-rule: never let acceleration change retrieval results).

Purpose: Turn SC2 from UNCERTAIN (mock-vector evidence) into a defensible recall@10=1.000 claim at production dimensionality with production embeddings.
Output: A hardened equivalence gate + a recorded live-brain real-embedding result.
