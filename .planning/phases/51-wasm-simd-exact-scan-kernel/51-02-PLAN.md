    Feature-detect + load (mirror `loadVectorIndex`'s try/catch→null shape, D-08): inside one try block — guard `dim % 4 === 0` and `data.length === count * dim` (return null otherwise, no throw); `const bytes = wasmBytes()`; `if (!WebAssembly.validate(bytes)) return null` (the blob carries v128/f32x4 ops, so validate is false on a runtime without SIMD — this IS the feature-detection per D-09 discretion); `const mod = new WebAssembly.Module(bytes)` (synchronous compile — the loader runs once at constructor time, off the per-query path).     Memory layout (adapt probe lines 89-99) — single shared `WebAssembly.Memory`, four contiguous regions `[query dim·4][matrix count·dim·4][recipNorms count·4][scores count·4]`. Pointers: `qPtr=0`, `mPtr=dim*4`, `rnPtr=mPtr+count*dim*4`, `outPtr=rnPtr+count*4`. Page-size from the total with headroom (`Math.ceil(total/65536)+4`), `maximum` set equal so the buffer never grows under it. Instantiate `new WebAssembly.Instance(mod, { env: { mem: memory } })`.

    Load the corpus ONCE at construction (not per query): `new Float32Array(memory.buffer, mPtr, count*dim).set(data)`. Precompute and store the per-row RECIPROCAL norms once into the recipNorms region as f32: for each r, `recipNorms[r] = norms[r] === 0 ? 0 : 1/norms[r]` (this folds the denom guard — a zero row-norm becomes 0 so the kernel emits score 0, matching cosineSimF32). Hold persistent f32 views over the query, scores, and (transiently) recipNorms regions.

    `scanCosine(query, qNorm)`: copy `query` into the query view; compute `recipQNorm = qNorm === 0 ? 0 : 1/qNorm`; call `scan(qPtr, mPtr, rnPtr, outPtr, recipQNorm, count, dim*4)`; return a COPY of the scores view (`scores.slice(0, count)`) so the caller holds a stable array (the view aliases reusable WASM memory). Do NOT recompute row norms (consume the precomputed reciprocals — discretion note). The module reads nothing from the DB and writes nothing (read-only on the graph).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| malformed/oversized index → WASM linear memory | `data`, `count`, `dim` from a derived sidecar drive region sizing and pointer arithmetic into `WebAssembly.Memory` |
| kernel fault → retrieval result | An instantiation/SIMD-unavailable fault must not corrupt or fabricate scores |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-21 | Information disclosure / DoS | `loadSimdKernel` region sizing | mitigate | Page-size memory from `count*dim` with `+4` headroom and `maximum===initial`; guard `data.length === count*dim` and `dim % 4 === 0` before allocating; persistent views are created with explicit `(buffer, ptr, length)` bounds matching the regions. A size/shape mismatch returns null → scalar fallback, never an out-of-bounds read. |
| T-51-22 | Tampering (results) | kernel instantiation / SIMD detect | mitigate | All detection/compile/instantiate in one try/catch → `return null` (D-08, mirrors loadVectorIndex). The loader NEVER throws; a fault degrades to scalar scan and is never authoritative (graph is source of truth, kernel is derived acceleration). |
| T-51-23 | Tampering (NaN/Infinity) | fused reciprocal-norm | mitigate | Reciprocal norms precomputed with `norms[r]===0 ? 0 : 1/norms[r]` and `recipQNorm` likewise, so a zero norm yields score 0 — matching cosineSimF32's `denom===0?0` guard; no NaN/Infinity can enter the score array. |
