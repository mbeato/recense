<objective>
Close the two round-4 regressions surfaced by 61-REVIEW.md (WR-01, WR-04) and re-confirmed in
61-VERIFICATION.md — both are code-provable defects on the corpus surface, independent of the
larger GAP-10 layout rework (plan 61-18).

- GAP-7: `focusCorpusProject` reads `CorpusGraph.zoom()` synchronously immediately after an
  animated `zoomToFit(CORPUS_FOCUS_TRANSITION_MS, …)`, so the MAX_ZOOM clamp evaluates the
  PRE-animation zoom. For a small cluster the animation can overshoot MAX_ZOOM unclamped, and the
  stale read can fire an instant `zoom(MAX_ZOOM, 0)` mid-transition, snapping the 500ms unfocus.
- GAP-8: the `humanTitle()` UUID scrub exists only in the `/index` handler; the `/graph?type=doc`
  node label ships raw `COALESCE(NULLIF(sch.value,''), nd.slug)`, which is the UUID slug for a
  schema-anchored doc whose backing schema node is empty — confirmed leaking on 3 live docs and
  drawn on node hover by corpus.js.

Purpose: restore the GAP-7 "animated, never a snap" and GAP-8 "never a raw UUID" guarantees on the
second (unguarded) code path each defect lives on, so the founder's live-install sign-off in plan
61-18 verifies a fully-fixed build. Output: two surgical patches + two locking tests.
</objective>
