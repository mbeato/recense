<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| doc markdown + fact values → browser DOM | rendering generated prose and fact values in the viz → XSS surface |
| HTTP request → generate spawn | a /doc or /doc/generate request triggers a subprocess + LLM spend |
| client → viz server | loopback-only; Host-header guarded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-08 | Tampering (XSS) | reader.js markdown render + fact values | mitigate | renderMarkdown escapes all text via escapeHtml before inserting markdown structure; node/fact values rendered via textContent (detail panel) — never innerHTML with raw fact values (T-10-12); test asserts a malicious fact value is escaped. |
| T-27-09 | Tampering (ref injection) | recense://fact|doc refs parsed from prose | mitigate | Refs matched by a strict UUID/slug regex (FACT_LINK/DOC_LINK), carried on data-attributes, resolved against ctx.idMap — never eval'd or used as a URL nav target (plain links stripped to text). |
| T-27-10 | Denial of Service (spend/spawn storm) | /doc lazy-gen + /doc/generate | mitigate | In-flight-slug Set prevents duplicate concurrent spawns; slug sanitized to [a-z0-9-]; generate is one CLI call; Host-header loopback guard blocks remote triggers. |
| T-27-11 | Elevation | server write attempt | mitigate | Viz server DB handle stays read-only; all writes happen only inside the spawned generate-doc CLI (single-writer + lock) — grep gate asserts no node/edge write SQL added to server.ts. |
| T-27-SC | Tampering | npm/pip/cargo installs | accept | Net-zero new runtime deps; no install tasks. |
</threat_model>
