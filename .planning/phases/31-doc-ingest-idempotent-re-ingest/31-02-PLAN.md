<objective>
Make `recense ingest-project <dir>` idempotent on re-run via a per-project cursor (REINGEST-02) and prove in-place belief reconciliation (REINGEST-01).

The cursor (`cursor:project:<scope>` in the SemanticStore meta table) stores a repo fingerprint. On re-run, if the fingerprint matches and `--force` is not set, the EXPENSIVE, non-deterministic agentic survey is SKIPPED entirely (D-04). This makes "a second run on an unchanged project produces zero new consolidated beliefs" (SC2) a STRUCTURAL guarantee, not a bet on the judge. Docs (Plan 01) are independently content-hashed, so an unchanged re-run is genuinely zero-new-beliefs end to end.

When the repo DID change, the survey re-runs and the existing PE-gated reconsolidation judge reconciles changed beliefs in place (tombstone+new) rather than minting duplicates (D-07) — bounded by the cursor so the judge is only exposed on real change.

Purpose: re-ingest stays cheap and correct; the cursor is load-bearing for correctness, not just speed.
Output: a fingerprint helper (git HEAD + dirty, mtime fallback), SemanticStore cursor read/skip-gate/write across both real-run branches, a `--force` flag, and the phase-gating dup-rate test.

Depends on Plan 01 (doc emission already wired). This plan adds the survey-gating cursor on top.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-supplied `<dir>` → `spawnSync('git', ...)` | The operator's path is passed as a git argument |
| stored cursor value → survey skip decision | A cursor row decides whether the expensive survey runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-INJECT | Tampering (command/arg injection) | `spawnSync('git', [...], ...)` with user `<dir>` | mitigate | ALWAYS the arg-array form `spawnSync('git', ['-C', dir, 'rev-parse', 'HEAD'], {stdio:'pipe'})` — never a shell string, never `shell:true`, never cwd tricks. `-C <dir>` passes the path as a discrete arg so a path with shell metacharacters cannot inject. `path.resolve(dir)` normalizes before use. Grep-gated in acceptance criteria. |
| T-31-CURSOR | Correctness (silent disable) | SemanticStore vs EpisodicStore for getMeta/setMeta | mitigate | The cursor uses `new SemanticStore(db, realClock, config)` on the SAME db handle. Passing EpisodicStore silently disables the cursor → re-surveys everything (correctness failure, not just perf). Acceptance criterion greps that the cursor object is a SemanticStore. |
| T-31-DRYCURSOR | Integrity (false ingest mark) | --dry-run cursor write | mitigate | --dry-run NEVER calls setMeta (D-09). A preview must not mark the project ingested. Tested: cursor unchanged after a dry-run. |
| T-31-GITERR | Availability (false re-survey/skip) | git status error handling | accept | On a git error during `status --porcelain`, treat the tree as clean (per RESEARCH) to avoid a false dirty→re-survey loop; worst case a genuinely-dirty tree is skipped once — acceptable, `--force` is the escape hatch. |
| T-31-SC | Tampering | npm installs | accept | No package installs — `child_process`/`fs` are Node built-ins; net-zero new runtime deps. |
</threat_model>
