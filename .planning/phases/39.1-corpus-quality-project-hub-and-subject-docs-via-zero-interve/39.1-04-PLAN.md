<objective>
One-time retroactive junk-doc cleanup CLI. It enumerates three DETERMINISTIC junk classes — (a) old schema-UUID chapter docs superseded by the restructure, (b) empty/never-filled stubs, (c) docs from noise-filtered schemas — and removes them safely: default dry-run prints a report and writes nothing; a real run (`--no-dry-run`) first takes a `VACUUM INTO` snapshot to `~/.config/recense/snapshots/` (the existing nightly-hygiene rollback path), aborts hard if the snapshot fails, then hard-deletes in FK-safe order inside a single IMMEDIATE transaction. Hard-delete is safe because docs are `origin='inferred'`, regenerable nodes — never evidence-backed facts (D-09 / CLAUDE.md guard).

Purpose: D-08 (deterministic junk definition, no LLM judgment, zero false-positive deletion risk) + D-09 (dry-run → approve → snapshot → hard-delete). Runs after Build because "obsolete chapter doc" is defined by the restructure (D-11).
Output: `src/adapter/cleanup-corpus-cli.ts`, a `cleanup-corpus` subcommand, and a test file covering predicates + snapshot guard + FK order.

OPEN ITEM FOR THE EXECUTOR: the live brain has NO database backup (single point of failure, per STATE.md). The destructive run (Task 3) is founder-gated: the founder must read and approve the dry-run report, and the snapshot must be confirmed readable, before a single row is deleted.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cleanup CLI → live production brain | Irreversible hard-delete on a DB with NO backup (single point of failure) |
| delete predicate → node set | A wrong predicate could match a non-junk / evidence-backed / still-referenced node |

This plan's MATERIAL threat is DATA LOSS, not network/auth. There is no network surface and no authentication surface; the destructive operation against the unbacked live brain is the entire risk model.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39.1-11 | Denial of Service / Destruction | over-deletion of a non-junk node | mitigate | D-08 deterministic structural predicates ONLY (no LLM judgment); the delete set is restricted to `type='doc'` `origin='inferred'` nodes matching one of the three structural classes; valid `scope:name` subject docs + the hub doc are excluded by construction; dry-run report + founder approval before any delete |
| T-39.1-12 | Destruction (no rollback) | snapshot skipped/failed before delete | mitigate | Snapshot-must-succeed invariant: VACUUM INTO to `~/.config/recense/snapshots/` is taken and verified readable BEFORE any DELETE; on snapshot failure the CLI aborts with exit 1 and deletes zero rows (Pitfall 5) |
| T-39.1-13 | Tampering (graph corruption) | partial / FK-violating delete | mitigate | FK-safe order node_doc → node_scope → edge → node_fts → node in ONE IMMEDIATE transaction; `PRAGMA foreign_key_check` verified empty after (Pitfall 4) |
| T-39.1-14 | Destruction | deleting an evidence-backed fact | mitigate | Delete set is `type='doc'` only; the "never delete evidence via decay" guard applies to fact/entity nodes — docs are explicitly excluded (D-09 / CLAUDE.md); Task 2 asserts no fact/entity node is ever in the delete set |
| T-39.1-15 | Tampering | concurrent sleep pass racing the delete | mitigate | Lockfile acquired for the real run (exit if held); run when no sleep pass active |

No package installs in this plan (no Package Legitimacy Gate needed). The cleanup operation is the supply-chain-equivalent risk concentration for this phase: it is gated behind a blocking human checkpoint that is NOT auto-approvable.
</threat_model>
