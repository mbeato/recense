<objective>
Add `promoteSubjects(scope)` to corpus-promoter.ts: the exhaust-gate's promotion engine. Stage 1 is LLM-free — it queries the scope's schemas (after schema induction has run) and applies the CREATE gate (mass/member threshold) and REFRESH gate (drift = members touched since the doc's generated_at). Stage 2 spends ONE Sonnet call per scope to propose a small set of LLM-named subjects, anchored against existing subject slugs for idempotency. It then creates the hub stub + subject stubs (empty, FTS-suppressed, origin=inferred), writes hub→subject doc_containment edges fill-in-place, and persists each subject's relatedSchemaIds set to a `subject-schema-ids:<subjectSlug>` meta key so Plan 03 generation can rebuild the schema set without a second LLM call. Schema clustering is demoted here: schemas inform mass/grouping but no longer map 1:1 to a doc.

Purpose: D-05 (two-stage cost model), D-06 (create-on-mass / refresh-on-drift), D-02 (LLM-named subjects), D-03 (schema demotion). This is the heart of the zero-intervention machinery.
Output: `promoteSubjects` (returning the set of proposed/created subjects + hub doc id + subject doc ids + which subjects need refresh), the per-subject schema-id meta persistence, and three new test files (tests/exhaust-gate.test.ts, tests/corpus-subject-promoter.test.ts, tests/corpus-hub-promoter.test.ts).
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39.1-04 | Tampering | subject-proposal name → slug | mitigate | Names length-bounded (<=200) and treated as labels only; normalized; never used unparameterized in SQL; never executed (Security V5) |

| T-39.1-06 | Tampering | hub stub / doc_containment edges | mitigate | BUG-2c fill-in-place: hub stub stays empty until generation; containment edges written in the same IMMEDIATE transaction so they never dangle on a tombstone (Pitfall 2) |
| T-39.1-07 | Elevation of Privilege | subject slug collision | accept | Single-tenant; scope is internal (sleep-pass derived), not external input; `scope:` prefix cannot collide with UUID chapter slugs |

No network/auth surface. No deletes. The material risks are self-confirmation (firewall), slug-drift duplicate accumulation (anchor-against-existing-list prompt + normalization), and dangling containment edges (fill-in-place + single transaction).
