<objective>
Add the generation layer for the new doc taxonomy: a project-hub generator (synthesized overview + LINKED subject index) and a subject-doc generator (LLM-named subject, fed by its schema set), plus the config knob the downstream drift gate needs. Schema-anchored chapter generation (`generateDocForSchema`) is left in place but is no longer the unit the sleep pass generates — that demotion happens in Plans 02/03.

Purpose: D-01/D-04 require the doc unit to become hub + subject, and D-04 specifically requires the hub index to be NAVIGABLE — each entry must be a `recense://doc/<docId>` ref so `writeDoc` materializes a `doc_link` edge (bare slug strings produce prose, not links). This plan delivers the two generation functions everything downstream calls. Building it first means Plans 02 (promoter) and 03 (orchestration) receive the generator contracts directly rather than exploring for them.
Output: `generateDocForHub`, `generateDocForSubject`, `buildHubDocPrompt`, `buildSubjectDocPrompt` in `doc-generator.ts`; `gatherFactsForSubject` in `doc-gather.ts`; `corpusSubjectDriftThreshold` in config; a new test file proving slug/shape contracts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → doc body | Subject names and generated prose are untrusted model output written into doc nodes |
| inferred members → mass/gather queries | Self-confirmation surface: inferred nodes must never feed generation input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39.1-01 | Tampering | gatherFactsForSubject member query | mitigate | D-37 firewall `n.origin != 'inferred'` on every member row — inferred docs/insights never feed the gather, blocking the self-confirmation feedback cycle (Pitfall 3) |
| T-39.1-02 | Tampering | generated doc body / subject name | mitigate | Subject names treated as untrusted labels only (never executed); generation is read-only (no strengthen/embed); verifyCitations rejects invented/tombstoned fact refs before persistence |
| T-39.1-03 | Information Disclosure | — | accept | Single-tenant local brain; no cross-tenant data path in this plan |

This plan has no network/auth surface and performs no deletes. The material risk is self-confirmation via inferred members (mitigated by the firewall) and empty-doc persistence (mitigated by the empty-output throw, inherited from generateDoc).
</threat_model>
