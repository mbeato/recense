<objective>
Build the core entity-dedup engine: an offline, LLM-free pass that finds near-duplicate
`type='entity'` nodes, merges each cluster into one canonical node, rewires all edges
onto the canonical, tombstones the duplicates, and writes an audit event per merge — all
under the engine's FK-safety and single-writer invariants.

Purpose: This is the load-bearing half of Phase 25. The CLI (Plan 02) and the live run
(Plan 03) are thin wrappers around the `EntityDedup` class this plan produces. The edge
rewiring is the exact failure class of the T-FK-01 bug, so correctness here is the whole
point.

Output: `src/consolidation/entity-dedup.ts` (EntityDedup class + run/plan API), an
`'entity_merge'` event_type, two additive store helpers, and a unit-test suite that
proves repeatability, FK-cleanliness, edge inheritance, tombstone-not-delete, origin
guard, and provenance.
</objective>

    Create `EntityDedup` in src/consolidation/entity-dedup.ts mirroring the consolidator's class +
    constructor-compiled-statement shape. Constructor: `(db, store, sink, clock, config)`.

    Public API: `run(opts: { threshold: number; dryRun: boolean }): { clusters: MergeCluster[]; mergedClusters: number; tombstoned: number }`.
    In dryRun mode, compute clusters and return them WITHOUT any db.transaction / writes.

    Algorithm (precision-first, two-stage, deterministic — D-01/D-02/D-03):
    - Snapshot: select `id, value, c, last_access, origin, prev_value, embedding` from
      `node WHERE type='entity' AND tombstoned=0`, ordered by id (stable). Compute all decisions
      against this pre-pass snapshot so ordering can't change the result.
    - Stage 1 (blocking): bucket nodes by `normalizeValue(node.value)` (reuse normalize.ts).
    - Stage 2 (confirm): within each bucket, decode embeddings (Buffer→Float32Array per Pitfall 5)
      and confirm a pair only when `cosineSimF32 >= threshold` (default passed in, 0.88). Build
      clusters as a union-find / transitive closure within the run (D-03).
    - Origin guard (D-04): exclude any node with a non-null/active `prev_value` (mid-reconciliation);
      do NOT merge a pair that crosses asserted_by_user↔inferred unless lexically near-identical
      (e.g. equal normalized value). Bias toward NOT merging on doubt.
    - Canonical selection (D-05): highest edge degree (use a degree query) → highest `c` → earliest
      `last_access` → lexicographic `id`. Canonical keeps its own id.
    - Sidecars (D-06): if canonical has no node_scope, inherit a duplicate's via upsertNodeScope; same
      for node_temporal if present. Read sidecars BEFORE tombstoning.

    Merge transaction — ALL cosine/cluster/canonical decisions computed BEFORE entering any
    `db.transaction` (T-02-ASYNC: no await inside). Per cluster, one `db.transaction(() => { ... }).immediate()`:
    1. Rewire every edge whose src or dst is a duplicate → canonical id. FK-safe order: `store.deleteEdge`
       the old edge FIRST, then `store.upsertEdge` the canonical-pointing edge (no FK-violation window —
       the exact T-FK-01 invariant). Drop self-loops (newSrc === newDst). On PK (src,dst,rel) collision,
       pass `w = max(existingW, rewiredW)` and latest last_access to upsertEdge (ON CONFLICT handles it).
    2. Assert `this.db.pragma('foreign_key_check')` is empty; throw to roll back if not (D-08 load-bearing guard).
    3. `store.tombstone(dup)` for each duplicate (never delete — D-09).
    4. `sink.emit({ event_type: 'entity_merge', node_id: canonicalId, candidate_id: dup, magnitude: cosine, payload: JSON.stringify({ merge_threshold, cosine, cluster_size }) })` per duplicate (D-10).

    No raw SQL writes to node/edge — route through store primitives only (single-writer, CONSOL-03).
    In particular, the edge rewire MUST delete the old edge via `store.deleteEdge(src, dst, rel)` (the
    primitive added in Task 1), NOT a raw `DELETE FROM edge`. The PATTERNS.md FK-safe-rewire excerpt that

    the single-writer mandate — copying it verbatim violates CONSOL-03.
    The ONLY raw SQL allowed is the read-side snapshot/degree SELECTs and the foreign_key_check pragma.
