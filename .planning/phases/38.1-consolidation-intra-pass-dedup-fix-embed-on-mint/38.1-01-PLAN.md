<objective>
Fix the intra-pass dedup blindness in the consolidator: during ONE consolidation pass, claims that arrive in that pass currently cannot dedup or contradict each other, because a mid-pass-minted node enters the graph with `embedding = NULL` and `topk` only scores nodes `WHERE embedding IS NOT NULL`. The minted node is invisible to later episodes in the same pass, so every claim lands as `'unrelated'` → permanent duplicate islands. This breaks the v6.0 bulk-ingest onboarding path (`ingest-project` into a small/empty graph consolidates the whole survey in one pass) and confounded the Phase 35 RANK-02 eval.

Fix is Option D (founder-locked): thread the already-computed claim vector (`claimVecs[claimIdx]`, computed in Phase A) into the `ClaimDecision` struct and call `setEmbedding(mintedId, decision.claimVec)` synchronously inside the Phase B transaction at every mint site where the minted node's `value == claimValue` (so the claim vector is provably the correct embedding for that node).

Purpose: a real correctness bug in the shipping onboarding path; also unblocks a fair Phase 35 RANK-02 re-test and must precede the v8.0 benchmark/gate phases so their baselines aren't frozen on a degenerate graph.
Output: `ClaimDecision.claimVec` field + embed-on-mint at the qualifying mint sites + a DEDUP-01 regression test reproducing `35-pass-proof.cjs` Scenario A in ONE pass.

This is off-distribution, load-bearing consolidation code. Surgical changes only — match existing style, no side-quest refactors, no scope-reduction "v1" stubs.
</objective>
